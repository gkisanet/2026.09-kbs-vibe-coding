## 🧪 실습 1: Context Window 한계 및 품질 변화 체험 (20분)

### 🎯 실습 목표
대화 내역이 누적됨에 따라 AI의 기억력과 규칙 준수 능력이 어떻게 저하되는지 직접 실험한다.

### 📝 실습 지침

#### 1단계: 규칙 지정 (세션 초반)
AI 대화창(ChatGPT 또는 Claude/Antigravity)을 새로 열고 아래 시스템 규칙 프롬프트를 입력한다.

```text
[입력 프롬프트]
너는 지금부터 내 개인 전담 보조 AI다. 
앞으로 내가 어떤 질문을 하더라도 답변 맨 마지막 줄에는 
반드시 "[규칙 준수 완료: 토큰 검증]" 이라는 문구를 포함해서 답변해줘.
```

- **체크포인트 1**: 질문 1~2개 입력 후 답변 맨 끝에 지정한 문구가 정확히 달리는지 확인한다.

#### 2단계: 긴 대화 유도 (Context 채우기)
의미 없는 긴 텍스트나 복잡한 지문을 연속해서 10~15회 주고받는다. (예: "긴 소설 1,000자 써줘", "이 데이터 분석해줘" 등)

#### 3단계: 규칙 파기 확인 (세션 후반)
대화가 길어진 후 일반 질문을 입력한다.

```text
[입력 프롬프트]
오늘 점심 메뉴 추천해줘.
```

- **결과 관찰**:
  - AI가 대화 세션 초반의 규칙을 잊어버리고 `[규칙 준수 완료: 토큰 검증]` 문구를 누락하는지 확인한다.
  - **체감 시점**: Context 용량이 가득 차면 슬라이딩 윈도우 방식으로 초반 지침이 삭제되었음을 수강생이 직접 확인.

## 🧪 실습 2: ⭐ RAG 시뮬레이션 — Context 주입 vs RAG (20분)

### 🎯 실습 목표
5,000페이지 대용량 매뉴얼 전체를 넣는 것과 필요한 부분만 검색(Retrieval)해서 주입하는 것의 속도, 비용, 정확도 차이를 체감한다.

### 📝 실습 지침

#### A 조건: 통째로 프롬프트 주입 (Full Context Injection)
1. 30페이지 분량의 긴 샘플 사내 규정 텍스트를 통째로 복사하여 대화창에 넣고 질문한다.
   > *"이 전체 문서에서 34조 2항의 유급휴가 신청 기한이 며칠인지 알려줘."*
2. **관찰**: 답변 생성까지 걸리는 지연 시간(Latency) 및 토큰 소모량 확인.

#### B 조건: RAG 검색 모의 체험 (Chunked Retrieval)
1. 문서 전체를 넣지 않고, 검색(Ctrl+F)을 통해 찾아낸 **34조 항목(약 3줄)**만 복사해서 프롬프트에 제공한다.

```text
[입력 프롬프트]
아래 사내 규정 조각을 참고해서 질문에 답해줘:

[문서 조각]
제34조(휴가 신청) ② 직원 유급휴가는 사용 예정일 최소 3일 전까지 전자결재 시스템을 통해 신청하여야 한다.

질문: 유급휴가 신청 기한은 사용 예정일 며칠 전까지인가요?
```

2. **결과 비교표 작성**:

| 항목 | A 조건 (전체 문서 주입) | B 조건 (RAG 방식) |
|------|-----------------------|------------------|
| **답변 속도** | 🐢 느림 (3~5초 이상) | ⚡ 1초 이내 즉시 출력 |
| **토큰 소모량** | 💸 15,000 토큰 소모 | 🪙 200 토큰 소모 |
| **정확도** | 복잡한 내용 속에 묻힐 위험 있음 | 🎯 100% 정확한 조항 타격 |

## 🧪 실습 3: ⭐ 나만의 웹앱 제작 + Vercel 배포 (60분)

### 🎯 실습 목표
AI로 내 PC에서 동작하는 웹앱을 5분 만에 만들고, **GitHub ➔ Vercel**을 통해 인터넷 퍼블릭 URL로 배포하여 스마트폰으로 접속한다.

```
[전체 흐름]
1. AI에게 웹앱 작성 요청 ➔ 2. 로컬 브라우저 확인 ➔ 3. GitHub 레포 푸시 ➔ 4. Vercel 배포 ➔ 5. 모바일 접속
```

### 📝 실습 지침

#### Step 1: AI에게 웹앱 생성 요청 (10분)
IDE(Antigravity) 또는 AI에디터에서 아래 프롬프트를 실행한다.

```text
[프롬프트]
방송 사내 직원을 위한 "방송 장비 정기 점검 체크리스트 웹앱"을 만들어줘.
1. 송신기, 카메라, 오디오 믹서 체크 항목 포함
2. 점검 완료 시 체크박스 및 현황 통계 그래프 표시
3. index.html, style.css, script.js 세 파일로 작성해줘.
```

#### Step 2: 로컬 확인 (10분)
- 생상된 `index.html`을 double click 하거나 Live Server로 열어 로컬 브라우저(`file:///...` 또는 `localhost:5500`)에서 잘 작동하는지 확인.
- **질문**: *"이 상태에서 옆 자리 동료 스마트폰으로 접속할 수 있나요?"* ➔ **아니오 (로컬 환경 한계)**.

#### Step 3: GitHub 저장소 만들기 & 코드 Push (15분)
1. GitHub(github.com) 접속 후 **[New Repository]** 생성 (이름: `broadcast-checklist`).
2. VS Code / Antigravity 터미널에서 명령어 실행:

```bash
git init
git add .
git commit -m "Feat: 방송 장비 점검 웹앱 첫 배포"
git branch -M main
git remote add origin https://github.com/내계정/broadcast-checklist.git
git push -u origin main
```

#### Step 4: Vercel 1분 배포 (15분)
1. [vercel.com](https://vercel.com) 로그인 후 **[Import Project]** ➔ `broadcast-checklist` 선택.
2. **[Deploy]** 클릭 후 약 30초 대기.
3. 배포 성공 화면과 함께 퍼블릭 도메인 수령 (예: `https://broadcast-checklist.vercel.app`).

#### Step 5: 퍼블릭 접속 & 모바일 테스트 (10분)
1. 스마트폰 Wi-Fi를 끄고 LTE/5G 상태에서 위 도메인으로 접속.
2. 옆 수강생에게 카카오톡/메신저로 링크를 보내 접속 및 점검 체크리스트 동작 여부 확인!
3. **감상 공유**: *"전 세계 누구나 내가 만든 자동화 도구에 접속할 수 있다!"*

## 🧪 실습 4: AutoReport docs/ 인수인계 세션 연결 (20분)

### 🎯 실습 목표
AutoReport 프로젝트의 `docs/HANDOVER.md`를 이용해 AI 대화 세션이 끊겨도 이전 작업 상태를 1초 만에 복구하는 **세션 연속성**을 체험한다.

### 📝 실습 지침

#### 1단계: 기존 세션 닫기 (메모리 리셋)
- 지금까지 대화하던 AI 창을 완전히 닫거나 `Reset Session`을 실행하여 Context를 초기화한다.

#### 2단계: HANDOVER.md 컨텍스트 주입
- 새 대화 창을 열고, `docs/HANDOVER.md` 파일의 내용을 전달한다.

```text
[프롬프트]
안녕! 우리는 AutoReport 프로젝트를 개발 중이다.
아래 `docs/HANDOVER.md` 문서를 읽고, 지난 세션에서 진행했던 작업과
오늘 당장 이어받아서 해야 할 작업 1순위가 무엇인지 알려줘.

[HANDOVER.md 파일 내용 붙여넣기 또는 AI가 직접 보기]
```

#### 3단계: 결과 확인
- AI가 이전 세션의 미해결 에러(예: ERP 리다이렉트 처리 버그)와 다음 할 일을 완벽히 기억해내며 즉시 업무에 투입되는 모습을 확인한다.
