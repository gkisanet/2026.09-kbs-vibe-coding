# 📘 AI 바이브 코딩을 활용한 업무 자동화 개발 — 교육 계획서

> **💡 핵심 메시지**: AI가 우리에게 준 진짜 변화는 **"AI가 일을 대신 해준다"** 가 아니라,
> **"내가 직접 만들 수 있게 됐다"** 는 것입니다.
> 그동안 개발자에게 부탁하기도 애매하고 나는 만들 수 없던 그 작은 도구들을,
> 이제 **AI와 대화하는 것만으로** 만들 수 있습니다.

# 🧭 들어가며 — 왜 하필 "바이브 코딩"인가

## 방송국에서 "AI 하자"는 말이 나오면 벌어지는 일

```
   "요즘 AI로 영상도 만들던데, 우리도 뭐 좀 해봅시다"
                    ↓
   → 영상 생성 AI를 알아본다
   → 데모는 멋있다
   → 그런데 막상 방송에 쓸 데가 마땅치 않다
                    ↓
   (몇 달 뒤) 예산은 썼는데 남은 게 없다
```

방송국은 **영상을 다루는 곳**이다 보니, AI 이야기가 나오면 자연스럽게 **생성형 영상 AI**부터 떠올립니다.
그런데 실제로 검토해 보면 **적용할 수 있는 지점이 생각보다 훨씬 적습니다.**

이 교육은 그 지점에서 시작합니다.

> ### 🎯 **"AI로 무엇을 할 수 있는가"가 아니라,
> ### "AI로 할 수 있는 것 중에서, 우리가 지금 실제로 할 수 있는 것은 무엇인가"**

---

## 🔑 AI를 업무에 쓰는 방법은 크게 3가지입니다

```
┌──────────────────────────────────────────────────────────────────┐
│  ① AI가 만든 것을 그대로 최종 결과물로 쓴다                       │
│  ────────────────────────────────────────                        │
│  AI에게 영상·이미지·음성을 만들게 해서 방송에 내보낸다             │
│  예) AI 수어통역, AI 자막, AI 배경 영상, AI 아나운서               │
│                                                                  │
│  ② AI를 프로그램 안에 넣어 실행 중에 판단시킨다                    │
│  ────────────────────────────────────────                        │
│  예) 문서를 자동 분류하는 시스템, AI 챗봇, AI 에이전트             │
│                                                                  │
│  ③ AI에게 "코드"를 만들게 해서 내 도구를 만든다   (바이브 코딩)   │
│  ────────────────────────────────────────                        │
│  예) 엑셀 정리 자동화, ERP 반복 입력 자동화, 사내 조회 웹앱        │
│                                                                  │
│                    ⭐ 이 교육이 다루는 것은 ③입니다               │
└──────────────────────────────────────────────────────────────────┘
```

---

### ⚠️ 먼저 용어 오해 하나를 풀고 갑니다 — "생성형 AI"

```
❌ 흔한 오해: "①번만 생성형 AI다. ChatGPT는 그냥 챗봇이다"
✅ 사실     : ①②③ 전부 생성형 AI를 씁니다. ChatGPT도 생성형 AI입니다.
```

**생성형 AI(Generative AI)** 란 **"새로운 콘텐츠를 만들어내는 AI"** 를 말합니다.
텍스트든 이미지든 영상이든 **코드든** 마찬가지입니다.
바이브 코딩에서 AI가 코드를 짜 주는 것도 **엄연히 생성**입니다.

> ### 🔑 **그러면 ①과 ③의 진짜 차이는 무엇인가?**
> **"무엇을 생성하게 하느냐"** 입니다.
>
> | | ① | ③ 바이브 코딩 |
> |---|---|---|
> | **AI가 만드는 것** | 방송에 나갈 **결과물 그 자체** | 도구의 **설계도(코드)** |
> | **틀렸는지 어떻게 아나** | ⚠️ 사람이 일일이 봐야 안다 | ✅ **실행해 보면 즉시 안다** |
> | **틀리면** | 그대로 방송 사고 | 고쳐서 다시 실행하면 그만 |
>
> ⭐ **이 차이 하나가 ①과 ③의 난이도를 완전히 갈라놓습니다.**
> ③이 쉬운 이유는 "생성형 AI가 아니라서"가 아니라,
> **생성된 결과물이 검증 가능하고, 틀려도 되돌릴 수 있기 때문**입니다.

> 📄 생성형 AI의 정확한 정의와, **"생성형 = 트랜스포머"가 왜 틀린 등식인지**는
> [2. AI의_이해.md](./2.%20AI의_이해.md) **Part 3.3** 에서 다룹니다.

## ① AI 생성물을 결과물로 쓰기 — 멋있지만, 방송에 쓸 데가 많지 않습니다

영상 생성 AI는 분명 놀랍습니다. 그런데 **잘 만드는 것과 방송에 쓸 수 있는 것은 다릅니다.**

```
┌──────────────────────────────────────────────────────────────────┐
│                                                                  │
│   영상·이미지 생성 AI는 "그럴듯함"을 잘 만들도록 발전했지,        │
│   "정확함"을 만들도록 발전한 것이 아닙니다.                       │
│                                                                  │
│   · 분위기 있는 배경 영상   → ✅ 잘합니다                         │
│   · 정보를 전달하는 영상    → ❌ 거의 못 합니다                   │
│                                                                  │
└──────────────────────────────────────────────────────────────────┘
```

방송국에서 다루는 영상의 상당수는 **정보를 전달하는 영상**입니다.
그래서 "멋진 영상"은 만들어도 **"쓸 수 있는 영상"으로 이어지지 않는 경우가 많습니다.

| 방송국에서 나오는 아이디어 | 현실 |
|--------------------------|------|
| AI 수어통역사 | ❌ 학습 데이터가 세계적으로도 수십 시간뿐. 검수에 통역사가 필요 |
| AI 실시간 자막 무검수 송출 | ❌ 고유명사 오인식 → 정정보도 사안 |
| AI 자동 편집 후 즉시 송출 | ❌ 맥락 오류·부적절 장면 위험 |
| AI 배경·타이틀 그래픽 | ✅ **이건 실제로 됩니다** (보기 좋으면 되는 영역) |

> 📄 **왜 그런지 끝까지 따라가 보고 싶다면**: [3-2. 사례연구_AI_수어통역.md](./3-2.%20사례연구_AI_수어통역.md)
> "AI로 수어통역사를 만들자"는 제안이 **왜 6개 층위에서 전부 막히는지**를 분해한 문서입니다.
> **지금 읽지 않아도 됩니다.** 다만 회의에서 이런 제안이 나왔을 때 근거로 쓰십시오.

## ② AI를 프로그램 안에 넣기 — 되긴 하지만, 생각보다 훨씬 어렵습니다

"우리 시스템에 AI를 붙이자"도 자주 나오는 이야기입니다. 여기엔 네 가지 벽이 있습니다.

```
┌──────────────────────────────────────────────────────────────────┐
│  💰 비용    실행할 때마다 API 요금이 발생합니다                    │
│             건수가 늘면 요금도 그대로 늘어납니다                   │
│                                                                  │
│  🔒 보안    입력 데이터가 매번 외부 AI 서버로 나갑니다             │
│             사내 문서·출연자 정보를 다루면 곧바로 걸립니다         │
│                                                                  │
│  🎲 환각    AI가 그럴듯한 오답을 내면 시스템이 잘못 동작합니다     │
│             그리고 오답 확률은 구조적으로 0이 될 수 없습니다       │
│                                                                  │
│  🔍 검증    ⭐ 가장 많이 놓치는 부분입니다                        │
│             AI 결과가 맞는지 사람이 전부 확인해야 한다면,          │
│             줄이려던 인건비가 그대로 남습니다                      │
└──────────────────────────────────────────────────────────────────┘
```

> ⚠️ **가장 흔한 실패 패턴**
> **"AI가 처리 → 사람이 전량 검수"** 구조를 만들어 놓고 자동화라고 부르는 것입니다.
> 생성이 100배 빨라져도 **검증 비용이 그대로면 전체 시간은 거의 줄지 않습니다.**

물론 **불가능하다는 뜻은 아닙니다.** 다만 예산·보안 심의·검증 체계를 갖춰야 하는 일이고,
**개인이나 한 부서가 오늘 시작할 수 있는 일은 아닙니다.**

## ③ ⭐ 바이브 코딩 — 이건 오늘, 혼자서, 사실상 공짜로 됩니다

그러면 우리가 실제로 얻을 수 있는 건 무엇일까요.

> ### 🔑 **AI가 만든 가장 큰 실질적 변화는 "코딩 장벽이 사라진 것"입니다.**

예전에는 이런 일이 있었습니다.

```
┌──────────────────────────────────────────────────────────────────┐
│  [예전]                                                           │
│                                                                  │
│   "매주 이 엑셀을 손으로 정리하는 데 2시간이 걸립니다"            │
│         ↓                                                        │
│   프로그램으로 만들면 5분이면 되는데…                             │
│         ↓                                                        │
│   · 개발팀에 요청하기엔 너무 사소하다                             │
│   · 외주 주기엔 예산이 안 나온다                                  │
│   · 내가 배우기엔 몇 달이 걸린다                                  │
│         ↓                                                        │
│   → 그냥 계속 손으로 한다  (몇 년째)                              │
└──────────────────────────────────────────────────────────────────┘
```

```
┌──────────────────────────────────────────────────────────────────┐
│  [지금]                                                           │
│                                                                  │
│   AI에게 말합니다.                                                │
│   "이런 형식의 엑셀을 읽어서 이렇게 정리해주는 도구를 만들어줘"    │
│         ↓                                                        │
│   · 코드가 나온다                                                 │
│   · 안 되면 "이 부분이 안 돼"라고 말하면 고쳐준다                 │
│   · 30분~2시간이면 동작하는 도구가 생긴다                         │
│         ↓                                                        │
│   → 다음 주부터 2시간이 5분이 된다                                │
└──────────────────────────────────────────────────────────────────┘
```

이게 **바이브 코딩(Vibe Coding)** 입니다.
**"AI와 대화하면서 내가 쓸 도구를 만드는 것"** 이고, 이 교육의 전부입니다.

## 🛡️ 그리고 이 방식은 구조적으로 안전합니다

바이브 코딩의 결정적 특징은 이것입니다.

```
┌──────────────────────────────────────────────────────────────────┐
│                                                                  │
│   ⭐ 완성된 도구 안에는 AI가 없습니다.                            │
│                                                                  │
│   AI는 "만들 때"만 쓰이고, "쓸 때"는 정해진 규칙대로만 돕니다.    │
│                                                                  │
└──────────────────────────────────────────────────────────────────┘

              [만들 때]                    [쓸 때]

   나 ──"이런 도구 만들어줘"──▶ AI        내 컴퓨터에서 혼자 실행
   나 ◀────── 코드 ──────────── AI        ✅ AI 호출 없음 → 비용 0원
                                          ✅ 데이터 외부 전송 없음
                                          ✅ 매번 똑같이 동작 (예측 가능)
```

앞에서 본 ①②의 문제들과 비교해 보십시오.

| | ① AI 생성물을<br>결과물로 | ② AI 탑재<br>시스템 | ③ **바이브 코딩** |
|---|:---:|:---:|:---:|
| **지금 당장 되는가** | 🔺 용도 한정 | ❌ 구축 필요 | ✅ **오늘** |
| **실행 비용** | 건당 발생 | 건당 발생 | ✅ **0원** |
| **데이터가 밖으로 나가나** | ⚠️ 나감 | ⚠️ 나감 | ✅ **안 나감** |
| **틀렸는지 알 수 있나** | ❌ 어려움 | 🔺 검수 필요 | ✅ **실행해 보면 즉시** |
| **누가 할 수 있나** | 전문 인력 | 개발팀 + 예산 | ✅ **담당자 본인** |
| **틀렸을 때 피해** | 방송 사고 | 시스템 오동작 | ✅ **거의 없음** |

> ### 🎯 **결론**
> **①②는 "언젠가 될 수도 있는 일"이고, ③은 "오늘 하면 되는 일"입니다.**
> 그리고 ③은 **가장 안전한 방식이면서, 체감 효과가 가장 빠릅니다.**

## 🧭 판단 기준을 하나 가져가십시오

이 교육이 끝나면 여러분 손에 남을 가장 실용적인 도구는 **판별 5문항**입니다.

```
  ① 데이터   학습·참고할 자료가 이미 대량으로 존재하는가?
  ② 정답     "그럴듯하면" 되는가, "정확해야만" 하는가?
  ③ 검증     틀렸는지 누가, 얼마나 싸게 알아내는가?
  ④ 시간     실시간이어야 하는가? 되돌릴 수 있는가?
  ⑤ 피해     틀렸을 때 피해 입는 특정한 사람이 있는가?
```

이 5개를 **AI 수어통역**에 대보면 **전부 ❌** 가 나옵니다.
그런데 **바이브 코딩으로 만드는 업무 자동화 도구**에 대보면 **전부 ✅** 가 나옵니다.

## 🎯 교육 개요

### 교육 과정명
**「AI 바이브 코딩으로 만드는 업무 자동화 — Context 관리부터 웹 배포까지」**

### 교육 대상 및 소요 시간
- **교육 대상**: 프로그래밍 경험이 없거나 적은 직장인 / 방송기술직 직원
- **교육 시간**: **총 6시간 (3시간 × 2일)**

### 왜 6시간 중 절반이 "Context 관리"인가

바이브 코딩을 해 보면 누구나 같은 벽에 부딪힙니다.

```
   처음 30분  : "우와, 진짜 되네?"
   1시간 뒤   : "왜 아까 고친 걸 또 되돌리지?"
   2시간 뒤   : "얘가 갑자기 멍청해졌는데?"
```

이건 **AI가 나빠진 게 아니라 Context(맥락)가 어질러진 것**이고,
**관리 방법이 정해져 있습니다.** 1일차 전체가 이것을 다룹니다.

> 이걸 모르면 바이브 코딩은 **"운이 좋으면 되는 일"** 이 되고,
> 알고 나면 **"항상 되는 일"** 이 됩니다. 그래서 절반을 씁니다.

| 2 | **Context 원리 이해** | Context Window, 토큰 개념, 대화 누적 시 AI의 품질 저하 원인을 설명할 수 있다 |
| 3 | **⭐ 모델 스펙 판독 능력** | OpenRouter 모델 페이지에서 `Context` / `Max Output` / 단가를 읽고, 128k와 1M의 실무 차이를 설명할 수 있다 |
| 4 | **AI 도구 선별 능력** | 작업 성격에 맞게 Chat UI, CLI Agent, Agentic IDE 중 적절한 도구를 선택할 수 있다 |
| 5 | **Context 관리 기법** | `AGENTS.md`, `HANDOVER.md` 등을 작성하여 AI와 지속 가능한 협업을 유지할 수 있다 |
| 6 | **로컬 자동화 앱 제작** | Chrome Extension 형태의 로컬 도구를 만들고 브라우저에서 실행할 수 있다 |
| 7 | **⭐ 퍼블릭 웹 배포** | GitHub 연동 및 Vercel 호스팅을 사용하여 내 웹앱을 전 세계 퍼블릭 URL로 공개할 수 있다 |
