# A. 개념어

## A-1. 하네스 (Harness)

> 🎬 **영상 원문**
> "하네스란 무엇인가 하면 쉽게는 클로드 코드"
> "**하네스가 원래 말 안장이잖아요**"
> "에이전트가 실수하지 않게 하는 장치를 모두 다 부른다고 볼 수 있을 것 같습니다"

**어원**: 말에 씌우는 **마구(馬具)** — 안장, 고삐, 굴레 전체를 가리키는 말.
소프트웨어에서는 원래 **test harness(테스트 하네스)** 라는 용어로 오래 쓰였습니다. "테스트 대상 코드를 실행시키기 위해 주변에 두르는 실행 껍데기"라는 뜻이죠.

**LLM 문맥에서의 뜻**:

```
┌────────────────────────────────────────────────────────────────┐
│  하네스 = 모델(가중치) 바깥에 둘러친 모든 것                     │
├────────────────────────────────────────────────────────────────┤
│                                                                │
│        ┌───────────────────────────────────┐                   │
│        │                                   │                   │
│        │   ┌───────────────────────┐       │                   │
│        │   │                       │       │                   │
│        │   │   ★ 모델 (LLM)        │       │  ← 이건 못 바꿈    │
│        │   │   가중치 + 토큰 생성   │       │    (남이 만듦)     │
│        │   │                       │       │                   │
│        │   └───────────────────────┘       │                   │
│        │                                   │                   │
│        │   ← 여기 전부가 "하네스" →         │  ← 이건 내가 만듦  │
│        │                                   │                   │
│        │   · 시스템 프롬프트                │                   │
│        │   · 도구(툴) 목록과 그 설명         │                   │
│        │   · 도구 실행 권한 / 승인 절차      │                   │
│        │   · 대화 기록을 어떻게 조립할지     │                   │
│        │   · 언제 요약(컴팩트)할지           │                   │
│        │   · 파일 읽기/쓰기 방식             │                   │
│        │   · 에러가 났을 때 무엇을 보여줄지  │                   │
│        │   · 루프 종료 조건                 │                   │
│        │   · 서브에이전트를 언제 부를지      │                   │
│        └───────────────────────────────────┘                   │
│                                                                │
└────────────────────────────────────────────────────────────────┘
```

> 🎯 **그래서 "클로드 코드도 하네스이다"** 는 이런 뜻입니다.
> 클로드 코드는 **모델이 아닙니다.** 클로드(모델)를 **감싸고 있는 프로그램**입니다.
> 같은 클로드 모델을 쓰더라도, 웹 채팅으로 쓸 때와 클로드 코드로 쓸 때 결과가 완전히 다른 이유가 이것입니다.
> → 자세한 내용은 **[4. 하네스](./4.%20하네스.md)**

## A-2. 루프 (Loop)

> 🎬 "에이전트들끼리의 동작 규칙까지 자율화하는 패턴"
> "절대로 더 이상 코딩 에이전트에 프롬프팅을 하면 안 된다. 너는 **루프를 만들어야 된다**"

**핵심 전환**:

```
[프롬프팅 방식]                   [루프 방식]
사람 → 지시 → 에이전트 → 결과      사람 → 목표+성공조건 → 에이전트
사람 → 지시 → 에이전트 → 결과                            ↓
사람 → 지시 → 에이전트 → 결과                        (스스로 실행)
      ↑                                                ↓
   매번 사람이 개입                                 (스스로 채점)
                                                       ↓
                                              별로면 ─┘ 다시
                                              됐으면 → 끝
```

**한 줄 정의**: **사람이 매 턴 개입하지 않아도 에이전트가 "다시 할지 / 끝낼지"를 스스로 판단하며 돌게 만드는 설계.**

> ⚠️ 오해 주의: "루프"라는 단어만 보면 `while` 문 같은 반복문을 떠올리기 쉬운데,
> **반복 자체가 아니라 "종료 조건을 에이전트에게 넘겼다"** 가 핵심입니다.
> → **[5. 루프](./5.%20루프.md)**

## A-3. 그래프 (Graph)

> 🎬 "루프 엔지니어링 돌아가는 작업을 **다시 결정론으로 끌고 오자**"
> "루프 엔지니어링의 어떤 확률적인 경로들을 그래프로 다시 만들자"

**수학에서의 그래프**: 점(노드) + 선(엣지)으로 된 구조. 막대그래프·꺾은선그래프의 그 그래프가 **아닙니다.**

```
   [요구사항 분석]
         │
         ▼
   [코드 작성] ◀────────┐
         │             │ 실패 시
         ▼             │
   [테스트 실행]────────┘
         │ 통과 시
         ▼
   [코드 리뷰]
         │
         ▼
      [배포]
```

**한 줄 정의**: **에이전트가 "다음에 뭘 할지" 스스로 정하게 두지 말고, 갈 수 있는 길과 조건을 미리 그림으로 못 박아 두는 설계.**

> ⚠️ 영상에서 대담자가 가장 갸웃한 지점이 여기입니다.
> "루프는 자율을 늘리는 방향, 그래프는 자율을 뺏는 방향인데 **갑자기 반대로 간 것 같다**"
> — 이 의문이 정당하고, 답은 **[6. 그래프](./6.%20그래프.md)** 에 있습니다.

## A-4. 컨텍스트 엔지니어링

> 🎬 "**개별 세션에서 필요한 것을 필요한 시간에 담자**"

프롬프트 엔지니어링이 **"어떻게 쓸까"** 라면, 컨텍스트 엔지니어링은 **"무엇을 넣고 무엇을 뺄까"** 입니다.
영상에서 4가지로 정리해 줍니다.

| # | 전략 | 구체적 기술 |
|:-:|------|-----------|
| 1 | **밖에 써놓고 필요할 때 꺼내기** | 메모리, 파일 기반 노트 |
| 2 | **필요한 것만 불러오기** | **스킬(Skills)**, 툴 검색(tool search) |
| 3 | **짧게 줄여서 보관하기** | 자동 요약(오토 컴팩트), 오래된 툴 실행 결과 삭제 |
| 4 | **아예 쪼개기** | 서브에이전트 / 멀티 에이전트 |

> 🔗 배포 교재 **[3-0. CONTEXT_관리.md](../교육자료%20배포/3-0.%20CONTEXT_관리.md)** 가 이 주제의 입문판입니다.
> → 심화는 **[3. 프롬프트에서 컨텍스트로](./3.%20프롬프트에서_컨텍스트_엔지니어링으로.md)**

## A-5. 계약 (Contract / 컨트랙)

> 🎬 "맨날 계약, 계약하던데" / "계약이라고 쓰니까 좀 이상한데, **컨트랙이라고 하면 그렇게 이상하진 않아요**"

**뜻**: 에이전트에게 **일 시작 전에 미리 못 박아 주는 명세서**. 새로 나온 개념이 아니라, 소프트웨어의 오래된 개념(인터페이스 명세, design by contract)을 에이전트에 옮겨온 것입니다.

영상이 든 예시를 표로 정리하면:

| 계약 항목 | 예시 |
|----------|------|
| **범위(scope)** | "너는 DB 전문이니까 다른 데는 건드리지 마" |
| **입력** | 무엇을 받아야 하는가 |
| **출력(산출물)** | 무엇을 어떤 형식으로 반환해야 하는가 |
| **사용 가능한 도구** | 어떤 툴을 쓸 수 있는가 |
| **권한** | 어디까지 건드려도 되는가 |
| **금지 사항** | "중간 실험 로그는 절대 지우지 말아라" |
| **에스컬레이션** | 어떤 상황에서 사람을 불러야 하는가 |

> 💡 **왜 갑자기 계약 얘기가 나왔나**: 에이전트가 **여러 명**이 되면서입니다.
> 혼자 일할 땐 그냥 시키면 되는데, 여러 에이전트가 같은 코드베이스를 동시에 만지면
> **서로 덮어쓰고 충돌**합니다. 그래서 사람 조직에서 쓰는 것과 똑같은 장치(R&R 명세)가 필요해진 것입니다.

## A-6. ReAct (리액트)

> 🎬 "ReAct 에이전트라는 거는 우리가 LLM 들어오면 툴 불러서 작업한다는 뜻이죠"
> "질문 들어오면 LLM이 툴 계속 실행해서 결과 내는 거. **지금의 우리 구조입니다**"

⚠️ **프론트엔드 라이브러리 React(리액트)와 전혀 다른 것입니다.** 이름만 같습니다.

**ReAct = Reasoning + Acting**. 2022년 논문에서 나온 패턴으로, LLM이 이렇게 반복합니다.

```
┌──────────────────────────────────────────────────┐
│  사용자: "이 프로젝트 테스트가 왜 깨지지?"          │
├──────────────────────────────────────────────────┤
│                                                  │
│  [Thought]  테스트 파일을 먼저 봐야겠다            │
│  [Action]   read_file("test_main.py")            │
│  [Observation] (파일 내용이 돌아옴)                │
│                    ↓                             │
│  [Thought]  import 하는 모듈이 없는 것 같다        │
│  [Action]   bash("ls src/")                      │
│  [Observation] (목록이 돌아옴)                     │
│                    ↓                             │
│  [Thought]  파일명이 오타났다. 고치자              │
│  [Action]   edit_file(...)                       │
│  [Observation] (성공)                             │
│                    ↓                             │
│  [Thought]  이제 됐다. 끝.                        │
│  → 최종 답변                                      │
│                                                  │
└──────────────────────────────────────────────────┘
```

> 🎯 **이게 왜 중요한가**
> **2025년에 "그래프 필요 없다"는 말이 나온 근거**가 바로 이것입니다.
> 사람이 플로우차트로 그려주던 절차를, ReAct 루프 하나가 **매번 즉석에서 만들어 냅니다.**
> 영상 표현: "워크플로우가 없어진 건 아니고, **ReAct라는 에이전트 안에 들어간 거죠.**"

## A-7. 스테이트 머신 (State Machine, 상태 기계)

> 🎬 "스테이트 머신 같은 느낌"
> "에이전트의 예측 불가능성을 **결정론적인 스테이트에 정의**하고, 어떤 **토폴로지** 안에다가 집어넣자"

**뜻**: 시스템이 가질 수 있는 **상태(state)** 를 유한하게 정해 놓고, **어떤 조건일 때 어떤 상태로 넘어가는지**를 전부 명시한 설계 방식.

가장 친숙한 예: **신호등**

```
[빨강] ──30초 경과──▶ [초록] ──25초 경과──▶ [노랑] ──5초 경과──▶ [빨강]
```

- 상태는 딱 3개뿐 (빨강/초록/노랑)
- 전이 조건이 전부 명시됨
- **"파랑"으로 갈 수 없음** — 정의되지 않았으니까

**LangGraph가 한 일**이 정확히 이것입니다. 에이전트를 신호등처럼 만든 것이죠.
"지금 상태 = 코드작성중" → "테스트 실패" → "상태 = 디버깅중". 정의되지 않은 곳으로는 못 갑니다.

- **토폴로지(topology)** = 노드들이 어떻게 연결돼 있는지의 배치도. 여기선 "그래프의 모양" 정도로 읽으면 됩니다.
- **결정론적(deterministic)** = 같은 입력이면 항상 같은 결과. LLM은 반대(확률적, stochastic)입니다.

## A-8. 힐 클라이밍 (Hill Climbing, 언덕 오르기)

> 🎬 "이 세 가지에서 문제가 발견되면 그 문제를 해결하는 **힐 클라이밍 루프**를 만들어야 된다"

**원래 뜻**: 최적화 알고리즘의 이름. 안개 낀 산에서 정상을 찾을 때, **주변을 더듬어 조금이라도 높은 쪽으로 한 발씩 옮기는** 방식.

```
        현재 위치
            ●
           ╱ ╲   ← 어느 쪽이 더 높나?
         ╱     ╲
       왼쪽    오른쪽(더 높음) → 오른쪽으로 한 발
```

**여기서의 뜻**: **시스템 자체를 점진적으로 개선하는 루프.**

| 구분 | 무엇을 반복하나 |
|------|---------------|
| **일반 검증 루프** | *결과물*을 고친다 (코드가 틀렸으니 코드를 고친다) |
| **힐 클라이밍 루프** | *만드는 방법*을 고친다 (계속 틀리네 → **스킬/프롬프트/절차 자체**를 고친다) |

영상의 예시가 정확합니다.

> "매일매일 뉴스 모아오기를 하고 있다고 가정했을 때, **점점점 뉴스를 더 잘 모아왔으면 좋겠다**"
> "별로면 그거를 또 어딘가에 피드백을 줘가지고 **스킬을 고치거나**"

## A-9. 이벤트 드리븐 (Event-Driven, 이벤트 기반)

> 🎬 "상황이 발생하면 대응할 수 있도록 에이전트를 켜놓으라는 얘기"
> "새 문서가 들어오거나, 일정이 트리거되거나, **웹훅**이 오거나"

**뜻**: "사람이 시켜서 도는" 게 아니라 **"바깥에서 무슨 일이 생기면 자동으로 도는"** 구조.

| 방식 | 시작 신호 | 방송국 비유 |
|------|----------|-----------|
| **요청 기반** (지금 대부분) | 사람이 프롬프트 입력 | 담당자가 편집실에 와서 일 시킴 |
| **스케줄 기반** (크론) | 정해진 시각 | 매일 아침 6시 자동 편성표 출력 |
| **이벤트 기반** | 외부 사건 발생 | **속보가 들어오면** 자동으로 자막 초안 생성 |

- **웹훅(webhook)** = 어떤 서비스에서 사건이 생기면 내 서버로 자동으로 알림을 쏴 주는 방식.
- **크론잡(cron job)** = 리눅스에서 "매일 몇 시에 이거 실행" 하고 예약해 두는 기능.

> 💡 영상 대담자가 "이거 갑자기 좀 다른 얘기 같은데요"라고 한 게 정확합니다.
> **개발할 때의 루프가 아니라, 만들어서 운영할 때의 루프**라서 결이 다릅니다.

## A-10. Human in the Loop (휴먼 인 더 루프)

> 🎬 "다른 방향으로 흘러가면 잡아줘야 되지 않냐? 이게 **휴먼 인 더 루프**랑 똑같잖아요"

**뜻**: 자동화된 과정 중간에 **사람의 판단을 의무적으로 끼워 넣는 것.**

영상에서 나온 비유가 아주 좋습니다.

> "이게 **교수와 대학원생의 관계**라고 생각하면 비슷한 느낌이기도 해요.
> 너가 알아서 일지 쓰면서 연구해라 하다가, 나는 일지 보고, 미팅 왔을 때
> '어떻게 연구하고 있니? 다른 데로 잘못 넘어갈 것 같으면 — 아니야, 이리로 다시 돌아와'"

방송에서 이미 하고 있는 것: **송출 전 심의**, **더블 체크**, **큐시트 승인**.

## A-11. 인컨텍스트 러닝 (In-Context Learning)

> 🎬 "그 시스템에 똑같은 프롬프트를 넣었는데 동작이 바뀌면 학습이 맞지" / "네, **인컨텍스트 러닝**이죠"

**뜻**: 가중치를 바꾸지 않고 **입력(컨텍스트)에 예시나 정보를 넣어서** 모델의 동작을 바꾸는 것.

이 대목은 배포 교재와 **정면으로 부딪히는 것처럼 보이므로 강사가 반드시 정리하고 가야 합니다.**

```
┌────────────────────────────────────────────────────────────────┐
│  "우리 회사 문서를 AI에 학습시켰다" — 이 말은 맞나?              │
├────────────────────────────────────────────────────────────────┤
│                                                                │
│  ❌ 가중치 학습(파인튜닝)인가?  → 아니다                        │
│     모델 파일은 1바이트도 안 바뀜                                │
│                                                                │
│  ✅ 시스템이 학습한 것인가?     → 그렇다                        │
│     같은 질문에 다른 답이 나옴 = 시스템 동작이 바뀜              │
│                                                                │
│  → 영상 결론: "모델을 학습한 건 아니고, 딥러닝적 학습은 아니지만  │
│               **시스템을 학습한 거죠**"                         │
│                                                                │
└────────────────────────────────────────────────────────────────┘
```

> 🎯 **강사용 정리 멘트 (권장)**
> "'학습시켰다'는 말은 두 가지를 가리킵니다.
> **① 모델 자체를 고치는 것(파인튜닝)** — 우리는 안 합니다.
> **② 시스템이 참고할 자료를 붙여주는 것(RAG·메모리·스킬)** — 이건 매일 합니다.
> 둘 다 겉으로는 '똑똑해졌다'로 보이지만 **비용이 1000배 차이납니다.**
> 그래서 배포 교재에서는 혼동을 막으려고 ②를 '학습이 아니다'라고 강하게 못 박았습니다.
> 정확히는 **'모델 학습이 아니다'** 입니다."

> 🔗 배포 교재 **2. AI의_이해.md**의 "5번 — 파일을 올려도 학습되지 않음" 항목과 짝을 이룹니다.

# B. 도구·제품

## B-1. ⭐ LiteLLM — "litellm도 이제 된다"

> 🎬 **영상 원문 (사용자가 가장 궁금해한 대목)**
> "지금 사실 제가 랭체인을 써가지고 이것저것 하고 있지만, 그걸 쓰는 이유는 사실
> **여러 개 LLM을 동시에 부를 수 있다는 것밖에 없거든요.**
> 근데 그건 사실 **LiteLLM도 되고 다 되는 거잖아요, 이제.**
> 그러니까 굳이 그걸 쓸 필요가 없긴 해요"

### 문제 상황부터 이해하기

AI 회사마다 **API 호출 방식이 다 다릅니다.**

```
OpenAI 방식:
  POST api.openai.com/v1/chat/completions
  { "model": "gpt-...", "messages": [...] }
  → 답: choices[0].message.content

Anthropic 방식:
  POST api.anthropic.com/v1/messages
  { "model": "claude-...", "max_tokens": 1024, "messages": [...] }
  → 답: content[0].text          ← 응답 구조가 다름!

Google 방식:
  또 다름
```

그래서 "우리 서비스는 GPT랑 클로드 둘 다 지원해요"를 만들려면
**회사마다 다른 코드를 짜야 했습니다.** 이게 옛날의 진짜 골칫거리였습니다.

### LiteLLM이 하는 일

```
┌──────────────────────────────────────────────────────────────┐
│                                                              │
│   [내 코드]  ── 한 가지 방식으로만 호출 ──▶  [LiteLLM]        │
│                                                │             │
│                            ┌───────────────────┼──────────┐  │
│                            ▼                   ▼          ▼  │
│                        [OpenAI]           [Anthropic]  [로컬] │
│                                                              │
│   → 모델 이름 문자열만 바꾸면 공급사가 바뀝니다               │
│     "gpt-..." → "claude-..." → "ollama/llama3"               │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

**LiteLLM = 100개 넘는 LLM 공급사를 하나의 통일된 방식(OpenAI 형식)으로 부르게 해 주는 얇은 변환기.**
파이썬 라이브러리로도 쓰고, **프록시 서버**로 띄워서 팀 전체가 그 서버 하나만 보게도 씁니다.

### 그래서 "litellm도 이제 된다"의 정확한 뜻

```
[2023년 논리]
 "여러 모델을 갈아끼우려면?"
      → LangChain을 써야 한다 (그게 거의 유일했으니까)
      → 그런데 LangChain은 그 김에 체인·에이전트·메모리까지 한 보따리로 딸려온다
      → 무겁고 배우기 어렵다

[2026년 논리]
 "여러 모델을 갈아끼우려면?"
      → LiteLLM 같은 얇은 도구면 충분하다 (그것만 딱 해 준다)
      → ⭐ 그러면 LangChain을 쓸 마지막 이유가 사라진다
```

> 🎯 **한 줄 번역**
> **"LangChain을 붙들고 있던 마지막 명분(다중 모델 지원)마저 이제 더 가벼운 도구로 해결되니까, LangChain을 굳이 쓸 이유가 없다."**

> 💡 **강사용 비유**
> LangChain이 **'만능 공구세트 가방'** 이라면, LiteLLM은 **'멀티 어댑터 플러그'** 하나입니다.
> 예전엔 어댑터가 공구세트 안에만 들어 있어서 세트를 통째로 사야 했는데,
> 지금은 어댑터만 따로 파니까 세트를 안 사도 되는 상황입니다.

## B-2. LangChain (랭체인)

> 🎬 "랭체인 같은 경우는 23년에 만들어진 거라서 사실 되게 옛날 거거든요"

- **등장**: 2022년 말. LLM 애플리케이션 프레임워크의 사실상 최초이자 최대 유행작.
- **핵심 아이디어**: "체인(Chain)" — 프롬프트 템플릿 → 모델 호출 → 결과 파싱 을 **레고처럼 이어 붙인다.**
- **왜 유행했나**: 2023년엔 이런 걸 다 손으로 짜야 했고, RAG·에이전트·메모리 예제가 전부 여기 있었습니다.
- **왜 식었나**:

| 비판 | 내용 |
|------|------|
| **과한 추상화** | 코드 세 줄이면 될 걸 클래스 다섯 개를 거쳐야 함 |
| **디버깅 지옥** | 뭐가 잘못됐는지 추적이 어려움 |
| **모델이 좋아짐** | 체인으로 쪼갤 필요 없이 그냥 한 번에 시키면 됨 |
| **대체재 등장** | 다중 모델은 LiteLLM, 도구 연결은 MCP, 에이전트 루프는 SDK가 기본 제공 |

> ⚠️ **"죽었다"는 아닙니다.** 여전히 많이 쓰이고 회사도 건재합니다.
> 영상의 뉘앙스는 **"새로 시작하는 사람이 굳이 여기서 출발할 이유는 줄었다"** 에 가깝습니다.

## B-3. LangGraph (랭그래프)

> 🎬 "그런 것들 하면서 만들어진 게 랭그래프였죠"
> "**난 랭그래프 전도사인데**" (진행자) ↔ "처음 나왔을 때 써보고 **너무 별로**라는 생각을 많이 했습니다" (게스트)

- **등장**: 2024년 초. LangChain 팀이 만든 **별도 라이브러리**.
- **왜 나왔나**: LangChain의 "체인"은 **한 방향으로만 흐릅니다.** 되돌아가거나(루프) 조건에 따라 갈라지는(분기) 걸 표현하기 어려웠습니다. LangGraph는 **사이클(순환)이 있는 그래프**를 지원합니다.
- **구성 요소**: 노드(할 일) + 엣지(다음 순서) + 조건부 엣지(if) + **State(모든 노드가 공유하는 상태 보따리)**

```
LangChain 의 체인          LangGraph 의 그래프
──────────────────         ────────────────────
A → B → C → 끝             A → B ─┬─(통과)→ C → 끝
                                  └─(실패)→ B (되돌아감)
직선                              순환 가능 + 분기 가능
```

- **평가**: 영상에서 두 사람의 의견이 갈립니다.
  - 진행자: "전도사" — 상태 머신이라는 **사상**이 좋다
  - 게스트: "진입장벽이 높다. 그런데 **그 사상을 구현하려면 랭그래프를 따라하는 게 제일 쉽긴 하다**"

## B-7. Manus (만수)

> 🎬 "그 **만수** 같은 사람들이 좋아하는 옛날 툴 실행 결과 다 없애버리는 거"

**Manus**(중국 스타트업의 범용 AI 에이전트 제품)를 한국어로 옮겨 부른 것으로 보입니다.
Manus 팀은 **에이전트 컨텍스트 관리 노하우를 공개적으로 많이 공유해 온 것으로 알려져 있고**, 그중 대표적인 기법이 영상에서 언급된 것입니다.

**"오래된 툴 실행 결과 지우기"란?**

```
[대화 기록]
 ... 100턴 전: read_file("a.py") → (파일 내용 500줄)   ← 이거 아직도 창에 남아있음
 ...  90턴 전: bash("ls")        → (목록 200줄)        ← 이것도
 ...  80턴 전: grep(...)         → (검색결과 300줄)     ← 이것도
 ...
 현재 턴: "그래서 결론이 뭐야?"

→ 지금 답하는 데는 저 1000줄이 하나도 필요 없다.
→ 그런데 매 요청마다 저걸 전부 다시 보낸다 (= 돈 + 성능 저하)
→ 그래서 "오래된 툴 결과는 그냥 삭제" 하는 전략
```

> 🔗 이 개념은 API 수준에서도 기능으로 존재합니다 (컨텍스트 편집 / context editing).

## B-8. Qwen (퀀/큐원)

> 🎬 "아까 말씀드린 Qwen 같은 친구들은 이런 거에 되게 힘들거든요"

알리바바가 만든 **오픈 웨이트 LLM 계열**. 가중치가 공개돼 있어 **내 컴퓨터/서버에서 직접 돌릴 수 있습니다.**
(→ 배포 교재 2번의 "경로 C: 로컬 실행"에 해당)

**여기서의 맥락**: 클로드·GPT 같은 최상위 모델은 복잡한 하네스를 잘 소화하는데,
Qwen급 오픈 모델은 **지시와 도구가 많아지면 헷갈려 한다** → "LLM이 똑똑해야만 잘하는 것 같아요"

> 🎯 **방송국 관점의 시사점**
> "보안 때문에 로컬 오픈 모델을 쓰겠다"고 하면, **하네스를 훨씬 얇게 설계해야 합니다.**
> 클로드 코드 쓰던 감각 그대로 로컬 모델에 옮기면 잘 안 됩니다.

## B-9. MCP (Model Context Protocol)

> 🎬 "거기에 들어가는 툴을 만들거나, 툴이나 스킬, **MCP를 만들거나**"

Anthropic이 2024년 11월에 공개한 **개방형 규약**. 애칭은 **"AI계의 USB-C"**.

```
[MCP 이전]
 클로드 코드 ── 전용 연동 코드 ──▶ 깃허브
 클로드 코드 ── 전용 연동 코드 ──▶ 슬랙        각 조합마다 따로 개발
 커서       ── 전용 연동 코드 ──▶ 깃허브       (N × M 개)

[MCP 이후]
 클로드 코드 ─┐                 ┌─ 깃허브 MCP 서버
 커서        ─┼─ MCP 규약 ──────┼─ 슬랙 MCP 서버       (N + M 개)
 코덱스      ─┘                 └─ 사내DB MCP 서버
```

**하네스와의 관계**: MCP는 하네스에 **도구를 꽂는 표준 규격**입니다.
영상에서 "하네스를 만든다"는 게 실제로는 "MCP나 스킬을 만든다"는 뜻이라고 정리하는 대목이 이것입니다.

## B-10. 스킬 (Skills)

> 🎬 "컨텍스트 중에서 필요한 것만 불러오자, 그게 바로 스킬이죠"
> "스킬도 굳이 따지면 근본적으로는 **그냥 프롬프트 덩어리잖아요**"

**정체**: 폴더 하나에 `SKILL.md`(설명서) + 참고 파일들을 넣어 둔 것.

**핵심 원리 — 점진적 공개(progressive disclosure)**:

```
평소 (기본 상태):
  컨텍스트에 들어있는 건 이것뿐 ↓
  ┌────────────────────────────────────────┐
  │ 스킬명: excel-report                    │
  │ 설명: 엑셀 보고서를 만들 때 사용        │  ← 두 줄 (약 20토큰)
  └────────────────────────────────────────┘

사용자가 "엑셀 보고서 만들어줘" 라고 했을 때:
  ┌────────────────────────────────────────┐
  │ (SKILL.md 전문을 그때 읽어들임)          │  ← 2000토큰
  │ 서식 규칙, 예시, 스크립트 경로...        │
  └────────────────────────────────────────┘
```

**영상에서의 논쟁 — 스킬은 정말 좋은가?**

| 찬성 | 비판 |
|------|------|
| 필요할 때만 로드 → 컨텍스트 절약 | 너무 많이 달면 판단이 흐려짐 |
| 개인 노하우를 매뉴얼로 자산화 | **효과를 측정하기가 매우 어렵다** |
| (영상의 베스트 사례) 박사과정 연구 방법을 스킬로 만들어 논문 억셉 | 스킬을 쓴/안 쓴 A/B 비교를 하려면 평가 데이터·환경이 필요 |

> 🎯 게스트의 냉정한 관찰이 인상적입니다.
> "제가 느끼기에는 **LLM이 더 똑똑해지는 방향이라기보다는 쓰는 사람이 편해지는 것 같거든요.**"

## D-2. 다이나믹 워크플로우 (Dynamic Workflow)

> 🎬 "한 번 시키면 그 일 시킨 게 딱 이렇게 스킬처럼 등록이 딱 되거든요"
> "나중에 비슷한 일을 시키면 그거를 또 쓰겠죠"
> "**스킬이랑 사실 뭐가 다른지 잘 모르겠어요**"

에이전트가 한 번 수행한 작업 절차를 **재사용 가능한 워크플로우로 자동 저장**하고,
피드백을 받으면 그 워크플로우를 조금씩 개선하는 기능.

```
1회차:  "주간 보고서 만들어줘"
        → 에이전트가 절차를 만들어 수행
        → ⭐ 그 절차가 워크플로우로 저장됨

2회차:  "주간 보고서 만들어줘"
        → 저장된 워크플로우를 재사용 (빠르고 일관됨)

3회차:  "여기 표 형식이 별로야"
        → 워크플로우가 수정되어 저장됨    ← 힐 클라이밍!
```

> 💡 게스트의 지적이 날카롭습니다. **"스킬이랑 뭐가 다른지 모르겠다."**
> 실제로 **거의 같은 것**입니다. 차이는 **누가 만드느냐** 뿐입니다.
> - 스킬 = 사람이 매뉴얼을 써 준다
> - 다이나믹 워크플로우 = 에이전트가 자기 매뉴얼을 스스로 쓴다

## D-5. AGENTS.md

> 🎬 "에이전트 MD에 내용을 꽉 채우는 것보다는 **계층적으로 만들어놓자**"
> "**꽉 채우면 얘가 바로 흘려버리니까**"

**영상이 강조한 요령 — 계층화**:

❌ 나쁜 방식                        ✅ 좋은 방식

AGENTS.md (5000줄)                 AGENTS.md (100줄, 지도 역할)

  다 읽고 다 흘림

# E. 은어·밈

| 표현 | 뜻 |
|------|-----|
| **AI 슬롭 (AI slop)** | AI가 대량 생산한 **내용은 없고 그럴듯하기만 한 글**. 영상: "그래프 엔지니어링 포스트의 99%는 AI 슬롭같이 보인다" |
| **fat harness** | 기능을 잔뜩 넣은 무거운 하네스. 반대말은 thin/minimal harness |
| **엑스 (X)** | 옛 트위터. AI 업계 담론이 가장 먼저 터지는 곳 |
| **클코** | 클로드 코드 |
| **딸깍** | "버튼 한 번 누르면 끝" — 손 안 대고 AI가 다 해준다는 한국 개발자 밈. "이제는 클로드 딸깍 하신다고요" |
| **RLVR** | Reinforcement Learning with **Verifiable Rewards**. "정답을 기계적으로 채점할 수 있는 문제로 학습시키기". 영상의 "검증할 수 있는 RVI 같은 걸 써야 되는 건데"는 이 표현으로 보입니다. **코딩과 수학이 AI에서 유독 빨리 발전한 이유**가 이것입니다 |
| **리워드 해킹 (reward hacking)** | 목표는 달성 못 했는데 **채점 기준만 만족시키는 꼼수**를 찾아내는 현상. 예: "테스트를 통과시켜라" → 테스트 코드를 지워버림 😅 |
| **20k** | 소셜 미디어에서 그 글이 받은 반응 규모 (좋아요/조회 2만) |
| **ICML** | 세계 최정상급 머신러닝 학회. "ICML 메인 논문 한 편 억셉됐습니다" = 대단한 성과 |
