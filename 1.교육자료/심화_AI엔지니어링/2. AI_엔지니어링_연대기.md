# 🕰 AI 엔지니어링 연대기 — 2023 → 2026

> **이 문서가 답하는 질문**: 왜 하필 **이 순서**로 용어가 등장했는가?
> **핵심 메시지**: **"각 시대는 앞 시대의 해법이 만들어낸 새 문제를 풀고 있다."**
> **읽는 요령**: 시대마다 **① 무엇이 병목이었나 → ② 무엇으로 풀었나 → ③ 그래서 무슨 새 문제가 생겼나** 이 세 칸만 따라가면 됩니다.

# Part 1. 2023년 — "다 망했어요"

## 1.1 그때 있었던 것

> 🎬 "23년에 보면 사실 에이전트가 있었습니다. Auto-GPT, BabyAGI"
> "이거 그때 써봤는데 어떠셨어요?" — "**되는 거 아무것도 없었죠**"

2023년 봄, ChatGPT가 세상을 뒤집은 직후, 사람들은 곧바로 이 생각을 했습니다.

```
"질문에 답만 하는 게 아니라,
 목표를 주면 알아서 검색하고, 파일 쓰고, 코드 돌리고,
 다 끝내주면 되잖아?"
```

Auto-GPT, BabyAGI가 그 시도였고, 깃허브 스타를 폭발적으로 받았습니다.

## 1.2 ⭐ 그런데 여기가 이 영상 전체에서 가장 중요한 문장입니다

> 🎬 "근데 이 당시에 하는 거랑 지금이랑 **내용은 거의 비슷하거든요.**
> 돌아가는 건 비슷해요. 그냥 주고 툴 콜링하거나 문제 풀기는 똑같단 말이에요.
> **근데 그 당시에는 이렇게 하면 다 망했어요.**"

```
┌──────────────────────────────────────────────────────────────────┐
│                                                                  │
│   2023년 Auto-GPT의 구조    ≒    2026년 클로드 코드의 구조        │
│                                                                  │
│   목표 받기                       목표 받기                       │
│      ↓                               ↓                           │
│   LLM이 다음 행동 결정             LLM이 다음 행동 결정            │
│      ↓                               ↓                           │
│   도구 실행                       도구 실행                       │
│      ↓                               ↓                           │
│   결과 보고 다시 판단              결과 보고 다시 판단             │
│      ↓                               ↓                           │
│   반복                            반복                            │
│                                                                  │
│   결과: 💥 전멸                    결과: ✅ 논문 억셉까지          │
│                                                                  │
│   ⭐ 아이디어는 3년 동안 그대로였다. 바뀐 것은 모델이다.           │
│                                                                  │
└──────────────────────────────────────────────────────────────────┘
```

> 🎯 **이 사실이 두 가지를 동시에 증명합니다**
>
> | 어느 쪽 근거로도 쓰인다 | 논리 |
> |---|---|
> | **하네스 무용론 쪽** | "봐라, 결국 **모델**이 다 한 거다. 구조는 3년 전 그대로다" |
> | **하네스 유용론 쪽** | "그래도 3년 전 모델을 지금 하네스에 넣으면 여전히 망가진다. **둘 다 필요하다**" |
>
> 영상도 이 지점에서 두 사람이 이렇게 주고받습니다.
> "엄청 잘 만들어진 하네스에 3년 전 모델 GPT-4 갖다 넣으면 다 망가진다는 거 아니에요?" — "맞습니다"
> "그러니까 미래도 마찬가지겠네요. **모델에 맞게 하네스도 같이 바뀌어야 된다**" — "그렇죠"

## 1.3 왜 망했나

| 원인 | 설명 | 지금은? |
|------|------|--------|
| **긴 맥락에서 성능 붕괴** | "긴 맥락이 늘어나면 성능이 다 떨어지니까" | 창도 커지고 장문 성능도 크게 개선 |
| **툴 콜링 미숙** | 도구 호출 형식을 자주 틀림 | 모델이 도구 사용을 학습으로 내재화 |
| **무한 루프** | 판단력이 약해 같은 짓 반복 | 자기 상태 추적 능력 향상 |
| **비용 폭발** | "하루 종일 돌면 토큰 다 나가니까 10불만 충전해라" | 여전히 문제 (→ 울트라 모드 이야기) |

## 1.4 그래서 나온 대응

> 🎬 "그 결과 나온 게 뭐냐면, 여러 개 LLM들을 **체인으로 연결**하거나 **모듈화**시켜서
> 이어 붙여서 A부터 B까지 가는 그런 과정들을 **플로우차트로 연결**하자"

**"에이전트를 못 믿겠으면, 절차를 사람이 정해 주자."** ← 2024년의 문이 열립니다.

# Part 2. 2024년 — 통제의 시대 (그래프 1세대)

## 2.1 병목과 해법

| | 내용 |
|---|---|
| **병목** | 에이전트의 자율성을 신뢰할 수 없음 |
| **해법** | 사람이 **플로우차트로 길을 미리 못 박고**, 각 지점에서만 LLM에게 작은 일을 시킴 |
| **대표 도구** | **LangGraph** |
| **사상** | 스테이트 머신 — 에이전트를 신호등으로 만들기 |

> 🎬 "완전 자율적으로 조영한 에이전트는 믿을 수가 없으니까,
> 이것을 우리가 **정해진 루트를 따라가게** 하는 방식으로 해서 문제를 해결하자.
> 여기서 여기로 가야 된다고 하는 그런 길 하나하나를 내가 **결정적으로 정해주자**"

## 2.2 실제로 어떻게 생겼나

```
┌───────────────────────────────────────────────────────────────────┐
│  2024년식 "AI 고객문의 처리 시스템" (전형적 예)                     │
├───────────────────────────────────────────────────────────────────┤
│                                                                   │
│   [문의 접수]                                                      │

│   ┌──────────────┐                                                │
│   │ ① 분류 LLM   │  "이 문의는 배송/환불/기술 중 뭐지?"  ← LLM 투입 │
│   └──────┬───────┘                                                │
│          │                                                        │
│    ┌─────┼─────┬──────────┐                                       │
│    ▼     ▼     ▼          ▼                                       │
│  [배송] [환불] [기술]  [기타→상담원]     ← 이 분기는 사람이 코딩     │
│    │     │     │                                                  │

│          ▼                                                        │

│          ▼                                                        │
│      [발송]                                                        │

│  ⭐ 전체 뼈대는 사람이 코드로 짬. LLM은 두 군데에서만 "일용직"으로 투입 │

> 🎬 "그런 거 옛날에는 다 **손으로 만들어 이어 붙였단 말이에요**"
> "네, 코드를 다 짜고 중간중간에 LLM이 들어가서 **툭 하나 일해 오고**, 또 들어가서 일해 오고"

## 2.3 ⭐ 놓치기 쉬운 결정적 사실

> 🎬 "그러니까 그때는 **역사적으로 컨텍스트는 고려할 필요가 없었어요.**
> 다 하나만 일하면 되니까. **길어질 필요가 없었거든요, 컨텍스트가**"

```
┌──────────────────────────────────────────────────────────────┐

├──────────────────────────────────────────────────────────────┤
│                                                              │
│  각 LLM 호출이 독립적인 단발 작업이었기 때문                   │
│                                                              │

│                                                              │

│                                                              │
│  ⭐ 컨텍스트가 문제가 되려면                                   │

│     그건 2025년 ReAct 에이전트 시대에 와서야 생긴 조건이다.    │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

> 🎯 이게 **"각 시대의 해법이 다음 시대의 문제를 만든다"** 의 첫 번째 실례입니다.

## 2.4 LangGraph에 대한 평가 — 영상 속 의견 충돌

| 진행자 | 게스트 |
|--------|--------|
| "난 **랭그래프 전도사**인데" | "처음 나왔을 때 써보고 **너무 별로**라는 생각을 많이 했습니다" |
| "이걸 누가 쓰지? **내가 쓰고 있는데**" | "좀 **진입장벽이 높고**…" |
| | "단지 랭그래프가 가지고 있는 **어떤 사상 같은 게 있죠.** 스테이트 머신이라든지…<br>**그걸 만드는 건 랭그래프를 따라 하는 게 제일 쉽긴 하죠**" |

> 💡 **이 평가가 정확합니다.**
> **라이브러리로서의 LangGraph**는 호불호가 갈리지만,
> **사상으로서의 "상태 머신 + 결정론적 전이"** 는 지금 2026년에 **다시 소환되고 있습니다.**
> → 6번 문서(그래프 2세대)로 이어집니다.

# Part 3. 2025년 — 자율의 시대 (플로우가 모델로 흡수됨)

## 3.1 무슨 일이 있었나

> 🎬 "아니, 우리가 이렇게 그래프로 만드는 복잡한 작업들을 **아직도 해야 되느냐. 그럴 필요 없다.**
> **클로드 코드를 봐라. 저렇게 잘하는데** 우리가 이런 거 하고 있어야 되겠느냐.
> **알아서 잘하는데 우리가 뭐 하러 만들어주냐**"

```
┌───────────────────────────────────────────────────────────────────┐
│  같은 고객문의 처리를 2025년식으로                                  │
├───────────────────────────────────────────────────────────────────┤
│                                                                   │
│   [문의 접수]                                                      │
│        │                                                          │
│        ▼                                                          │
│   ┌────────────────────────────────────────────────────┐          │
│   │                                                    │          │
│   │   ★ ReAct 에이전트 하나                             │          │
│   │                                                    │          │
│   │   도구: [카테고리조회] [배송DB] [환불DB]            │          │
│   │        [기술문서검색] [상담원호출] [메일발송]        │          │
│   │                                                    │          │
│   │   → "이건 환불 건이네" (스스로 판단)                 │          │
│   │   → 환불DB 조회 (스스로 도구 선택)                   │          │
│   │   → "정보가 부족하네" → 기술문서도 검색              │          │
│   │   → 답변 작성 → 발송                                │          │
│   │                                                    │          │
│   └────────────────────────────────────────────────────┘          │
│                                                                   │
│  ⭐ 사람이 짠 것: 도구 목록 + 시스템 프롬프트. 그게 전부.           │
│     분기·순서·판단은 전부 모델이 매번 즉석에서 만든다.              │
│                                                                   │
└───────────────────────────────────────────────────────────────────┘
```

## 3.2 ⭐ "워크플로우가 사라진 게 아니다"

> 🎬 "근데 그게 사실 **워크플로우가 없어진 건 아니고, ReAct라는 에이전트 안에 들어간 거죠.**"

```
   2024년                          2025년
   ────────                        ────────
   워크플로우가                     워크플로우가
   [사람의 코드] 안에 있었다   →    [모델의 판단] 안으로 들어갔다

   눈에 보임 (파이썬 파일)          눈에 안 보임 (매번 새로 생성)
   고정됨                          유동적
   디버깅 가능                      추적이 어려움
```

> 🎯 이것을 영상은 **"추상화 계층으로 확 들어와 버렸고"** 라고 표현합니다.
> 프로그래밍 역사에서 늘 있어온 일입니다.
> 어셈블리 → C → 파이썬으로 올라올 때마다 "아래층이 안 보이게" 되었죠.
> (영상에서도 어셈블리 비유가 나옵니다 → 4번 문서)

## 3.3 그러자 곧바로 새 문제가 생겼습니다

> 🎬 "에이전트가 일을 잘하니까 **계속 어려운 걸 시키자. 점점 하고 싶은 게 늘어나요.**
> 그러다 보니까 이제는 에이전트한테 **롱 호라이즌 태스크**를 시키기 시작합니다."

- **롱 호라이즌 태스크(long-horizon task)** = 여러 단계를 오래 거쳐야 끝나는 일. (예: "이 레포 전체를 마이그레이션해")
- 오래 돈다 = **대화가 계속 쌓인다** = **컨텍스트가 찬다**

> 🎬 "이 친구들은 그러다 보니까 이제부터는 **컨텍스트가 중요해집니다.**
> 컨텍스트가 무조건 쌓이게 되고… 그런 것들을 어떻게 관리하느냐
> 이런 게 생기면서 그냥 **새로운 단어가 생긴 것**이 바로 이거라고 할 수 있습니다. — 컨텍스트 엔지니어링"

> 📌 **여기가 이 연대기의 논리적 심장부입니다.**
> ```
> 모델이 좋아졌다
>   → 사람이 짜던 절차를 모델이 대신 만든다 (수축)
>   → 그래서 사람이 더 큰 일을 시킨다
>   → 큰 일 = 긴 세션 = 컨텍스트 오염 (새 문제)
>   → 컨텍스트를 관리하는 새 층이 생긴다 (팽창)
> ```

# Part 4. 2025년 후반 — 컨텍스트에서 하네스로

## 4.1 컨텍스트 엔지니어링의 4가지 무기

> 🎬 "개별 세션에서 **필요한 것을 필요한 시간에 담자**"

| # | 전략 | 기술 | 비유 |
|:-:|------|------|------|
| 1 | 밖에 써놓고 꺼내오기 | 메모리, 노트 파일 | 수첩에 적어 두기 |
| 2 | 필요한 것만 불러오기 | **스킬**, 툴 검색 | 필요할 때 매뉴얼 펴기 |
| 3 | 짧게 줄여 보관하기 | 오토 컴팩트, 오래된 툴 결과 삭제 | 회의록 요약본만 남기기 |
| 4 | 아예 쪼개기 | 서브에이전트 | 팀원에게 나눠 주기 |

> 💡 게스트의 냉정한 논평이 여기서도 나옵니다.
> "제가 느끼기에는 **LLM이 더 똑똑해지는 방향이라기보다는 쓰는 사람이 편해지는 것 같거든요.**
> 스킬도 굳이 따지면 근본적으로는 **그냥 프롬프트 덩어리잖아요.**"
>
> → 이 지적은 타당합니다. 컨텍스트 엔지니어링은 **모델의 성능을 올리는 게 아니라,
> 모델이 이미 가진 성능을 낭비하지 않게 하는 기술**에 가깝습니다.

## 4.2 그런데 창만 관리해선 안 되더라 — 검증 문제의 등장

> 🎬 "너무 긴 일을 하다 보면 **중간에 다 안 하고 끝냈다고 주장하는** 그런 일들이 생기더라는 거예요"
> "그럼 이제 어떻게 해요? 다시 이어서 해야죠. 근데 이어서 하니까
> 이 친구들도 '많이 해놨는데 끝난 거 아닌가? 끝냈다' **그런 줄 알고 그냥 끝내버리더라는 거죠**"

```
┌───────────────────────────────────────────────────────────────┐
│  실무자가 다 겪는 그 현상                                       │
├───────────────────────────────────────────────────────────────┤
│                                                               │
│   나: "이 기능 전부 구현해줘" (파일 12개 수정 필요)             │
│   AI: (7개 고침) "✅ 완료했습니다!"                            │
│   나: "아직 5개 남았는데?"                                     │
│   AI: "죄송합니다, 이어서 하겠습니다" (2개 더 고침)             │
│        "✅ 완료했습니다!"                                      │
│   나: "……"                                                    │
│                                                               │
│  ⭐ 이걸 사람이 매번 잡아내야 한다면 자율화는 불가능하다.        │
│                                                               │
└───────────────────────────────────────────────────────────────┘
```

## 4.3 ⭐ 결론: 0/1로 떨어지는 채점기를 다시 넣어라

> 🎬 "**AI를 믿으면 안 되겠구나**… AI가 한 것을 검증할 수 있는
> 다시 한 번 **결정적 요소**를 도입해야 된다"
> "다시 한 번 뭔가 **0, 1로 딱 떨어지는 요소**를 도입해서 문제를 해결해야 된다. **CI 같은 게 역할이 될 거고요**"

- **CI (Continuous Integration)** = 코드가 바뀔 때마다 자동으로 테스트를 돌려서 통과/실패를 알려주는 시스템.
- 핵심은 **"AI가 아닌 것이 채점해야 한다"** 는 점입니다. AI에게 "다 했니?"라고 물으면 "네"라고 하니까요.

> 🎯 **이 대목이 이 영상 전체에서 실무적으로 가장 값집니다.**
> 그리고 배포 교재의 바이브 코딩 파트와 정확히 이어집니다.
> "이건 사실 우리 **바이브 코딩 얘기할 때 많이 한 얘기죠. 검증을 더 많이 붙여야 된다**"

## 4.4 그래서 하네스라는 우산이 펼쳐집니다

> 🎬 "하네스는 **에이전트가 실수하지 않게 하는 장치를 모두 다** 부른다고 볼 수 있을 것 같습니다.
> **내가 원하는 작업을 똑바로 하게 하기 위한 모든 장치**를 다 하네스라고 부르면 제일 좋은 것 같아요"

이제 컨텍스트 관리는 **하네스의 부분집합**이 됩니다.

```
┌─────────────────────────────────────────────────┐
│  하네스                                          │
│  ┌──────────────────────┐                       │
│  │  컨텍스트 엔지니어링   │  ← 창에 뭘 넣고 뺄지  │
│  └──────────────────────┘                       │
│  + 도구 설계 / 권한 / 승인 절차                   │
│  + 검증 장치 (CI, 테스트, 검증 에이전트)          │
│  + 로그·에러 노출 방식                            │
│  + 문서 계층 구조 (AGENTS.md)                    │
│  + 종료 조건                                     │
└─────────────────────────────────────────────────┘
```

> 🎬 영상도 이 겹침을 인정합니다.
> "**벌써부터 좀 오버랩되고 있어요.** 컨텍스트 엔지니어링이랑 약간 오버랩되고 있긴 합니다…
> 사실은 좀 **합쳐지고 있는** 거라고 볼 수 있죠"

# Part 5. 2026년 — 루프와 그래프

## 5.1 무엇이 달라졌나: **에이전트가 여러 명이 되었다**

> 🎬 "우리가 큰 프로젝트가 주어져서 이런 것들을 가지고 **여러 에이전트가 관리하는 복잡한 어떤 환경** 속에서,
> 어떻게 하면 이 친구들의 작업들을 원활하게 유지할 것이냐,
> 그리고 어떻게 하면 이 친구들끼리 **서로 싸우지 않고 충돌하지 않고** 일을 잘하게 할 것이냐"

그래서 **계약(contract)** 이라는 말이 나옵니다. (→ 1번 문서 A-5)
사람 조직이 커지면 R&R 문서가 필요해지는 것과 **완전히 같은 이유**입니다.

## 5.2 루프 (자율의 극대화)

> 🎬 "정확한 하네스와 지침과 계약으로 만들어진 어떤 훌륭한 **일인분 에이전트**가 있을 때,
> 얘네들로 만들어진 **시스템이 자율적으로 가게 하자**. 이것까지 가는 것이 루프 엔지니어링"

두 가지 사건이 거의 동시에 이 말을 밀어 올립니다.

| 사건 | 내용 |
|------|------|
| 널리 퍼진 글 | **"코딩 에이전트에 프롬프팅하지 마라. 루프를 만들어라"** |
| 보리스 체르니(클로드 코드 제작자) 발언 | **"우리는 더 이상 클로드 코드에 프롬프팅하지 않는다"** |

→ 자세한 내용은 **[5. 루프](./5.%20루프.md)**

## 5.3 그래프 2세대 (통제로 회귀)

> 🎬 "그래프는 방금 설명드렸던 루프 엔지니어링 돌아가는 작업을 **다시 결정론으로 끌고 오자**"

그런데 영상의 대담자가 곧바로 반문합니다.

> 🎬 "근데 그래프 엔지니어링은 갑자기… **여기서 발전이 아니라 루프의 반대로 갔잖아요, 지금**"
> "그러니까 **갑자기 반대로 갔다는 느낌**이 들거든요. 제가 이해한 게 맞나요?"
> — "**저도 그렇게 생각하고 있어요.**"
> "어떤 사람들의 의견은 **돌아간 게 아니냐, 다시 24년으로.** 그런 얘기를 할 수 있긴 하거든요"

→ 이 의문에 대한 답이 **[6. 그래프](./6.%20그래프.md)** 전체입니다.
