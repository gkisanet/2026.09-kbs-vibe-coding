### 있을 때 vs 없을 때

| 상황 | AGENTS.md 없음 | AGENTS.md 있음 |
|------|---------------|---------------|
| 새 대화를 시작할 때 | "우리 프로젝트는 이렇고…" 매번 설명 | 즉시 파악하고 시작 |
| 코드 스타일 | 대화마다 스타일이 바뀜 | 일관되게 유지 |
| 위험한 파일 | 멋대로 고침 😱 | 건드리지 않음 |
| 작업 범위 | 안 시킨 것까지 대량 수정 | 시킨 것만 수정 |
| 도구를 바꿨을 때 | 처음부터 다시 설명 | 그대로 읽힘 ✅ |

> ### 🔑 **핵심 원칙**
> **"두 번 이상 설명하게 되는 것은 전부 AGENTS.md에 적는다."**

## 2. 📐 좋은 AGENTS.md의 4가지 조건

```
  ① 짧을 것        규칙이 길면 AI가 뒤쪽을 흘립니다.
                    ⭐ A4 1~2장, 12,000자 이내. 짧을수록 잘 지킵니다.

  ② 구체적일 것    ❌ "코드를 깔끔하게 짜라"        (판단 불가)
                    ✅ "함수는 50줄을 넘기지 마라"   (판단 가능)

  ③ 금지를 명시할 것  AI는 "하라"보다 "하지 마라"를 더 잘 지킵니다.
                    ⭐ Don't 섹션이 실제로 제일 효과가 큽니다.

  ④ 계속 고칠 것    AI가 같은 실수를 두 번 하면 → 그 즉시 한 줄 추가.
                    이 파일은 완성되는 게 아니라 자라납니다.
```

## 3. 📄 템플릿 (아래 회색 블록 전체를 복사하십시오)

> **저장 위치**: 프로젝트 폴더 최상단 → 파일명 **`AGENTS.md`**
> **`[대괄호]` 부분은 반드시 본인 프로젝트 내용으로 바꾸십시오.** 그대로 두면 아무 효과가 없습니다.

````markdown
# AGENTS.md

이 문서는 이 프로젝트에서 AI 에이전트가 지켜야 할 규칙이다.
작업을 시작하기 전에 반드시 이 문서를 먼저 읽는다.

## 1. 프로젝트 개요

- **무엇을 만드는가**: [예: 사내 ERP의 반복 입력을 자동화하는 Chrome Extension]
- **누가 쓰는가**: [예: 기술운용부 직원 5명, 사내망 PC에서만 사용]
- **왜 만드는가**: [예: 매주 2시간 걸리는 수기 입력을 5분으로 줄이기 위해]
- **개발자 수준**: 프로그래밍 비전공자다. **설명은 쉬운 말로 해라.**

## 2. 기술 스택

- **언어**: [예: JavaScript (ES6+), HTML, CSS]
- **런타임**: [예: Node.js LTS]
- **프레임워크**: [예: 없음 / Vue 3 / Express]
- **금지**: 여기 적히지 않은 라이브러리를 임의로 추가하지 마라.
  꼭 필요하면 **먼저 이유를 설명하고 승인을 받아라.**

## 3. 실행 방법

```
[예:
  npm install      # 최초 1회
  npm run dev      # 개발 서버 실행 → http://localhost:5173
]
```

## 4. 반드시 지킬 것 (Do)

- 코드를 고치기 전에 **무엇을 왜 고칠지 한 줄로 먼저 말해라.**
- 한 번에 **한 가지 문제만** 고쳐라.
- 파일을 새로 만들기 전에 **기존 파일에 넣을 수 없는지 먼저 확인해라.**
- 주석과 사용자에게 보이는 문구는 **한국어**로 작성해라.
- 에러가 났을 때는 **추측하지 말고, 먼저 실제 값을 출력해서 확인해라.**
- 확신이 없으면 **모른다고 말해라.** 그럴듯하게 지어내지 마라.

## 5. 절대 하지 말 것 (Don't) ⭐ 가장 중요

- ❌ **요청하지 않은 파일을 수정하지 마라.**
- ❌ **기존 기능을 "개선"이라는 이유로 임의로 바꾸지 마라.**
- ❌ 아래 파일들은 **읽기만 하고 절대 수정하지 마라**:
  - `[예: manifest.json, data/*.json, .env]`
- ❌ **API 키·비밀번호·사내 실데이터를 코드에 직접 써 넣지 마라.**
  반드시 `.env` 를 쓰고, `.gitignore` 에 `.env` 를 넣어라.
- ❌ `git push --force`, `rm -rf`, DB 삭제 등 **되돌릴 수 없는 명령을
  실행하기 전에는 반드시 먼저 물어봐라.**
- ❌ 한 번에 **파일 5개 이상을 동시에 고치지 마라.** 나눠서 진행해라.

## 6. 코드 스타일

- 들여쓰기: [예: 스페이스 2칸]
- 변수·함수명: [예: camelCase] / 상수: [예: UPPER_SNAKE_CASE]
- 함수는 **50줄을 넘기지 마라.** 넘으면 나눠라.
- **왜 그렇게 했는지**를 주석으로 남겨라. (무엇을 하는지는 코드를 보면 안다)

## 7. 문서 관리 (Context 유지 규칙)

작업 후 아래 문서를 갱신한다. 이것이 다음 대화의 AI에게 넘길 기억이다.

| 파일 | 역할 | 언제 갱신 |
|------|------|----------|
| `docs/CONTEXT.md`  | 프로젝트 구조·설계 | 구조가 바뀌었을 때 |
| `docs/TASKS.md`    | 할 일 / 진행 상황 | 작업 시작·완료 시 |
| `docs/CHANGELOG.md`| 변경 이력 | 기능이 추가·수정될 때 |
| `docs/HANDOVER.md` | ⭐ 다음 세션 인수인계 | **대화를 끝낼 때마다** |

- 새 대화를 시작하면 **`docs/HANDOVER.md` 를 먼저 읽고** 상황을 파악해라.
- 대화가 길어져서 정리가 필요하면, **먼저 `HANDOVER.md` 를 갱신하자고 제안해라.**

## 8. 작업 절차

1. 요청을 **내 말로 한 줄 요약**해서 되물어 확인한다
2. 고칠 파일 목록을 먼저 제시한다
3. 승인을 받고 수정한다
4. **실행해서 동작을 확인한다** (되는지 안 되는지 추측하지 않는다)
5. `docs/` 문서를 갱신한다

## 9. 보안 (사내 프로젝트 필수)

- 사내 실제 데이터(사번, 이름, 주소, 계정)를 **예시로도 쓰지 마라.**
  예시가 필요하면 `홍길동`, `test@example.com` 같은 가짜 값을 써라.
- 외부로 데이터를 전송하는 코드를 만들 때는 **반드시 먼저 알려라.**
- `.gitignore` 에 최소한 다음을 포함해라: `.env`, `node_modules/`, `*.xlsx`
````

## 4. 🌍 글로벌 규칙 (`~/.gemini/GEMINI.md`) 추천 양식

프로젝트와 무관하게 **"나는 AI가 이렇게 말해 주면 좋겠다"** 는 개인 취향을 적는 곳입니다.
Antigravity의 **Customizations → Rules → `+ Global`** 에 넣으십시오.

```markdown
# 개인 작업 규칙

## 응대 방식
- 한국어로 답한다.
- 나는 프로그래밍 비전공자다. 전문 용어를 쓸 때는 괄호로 짧게 풀어 준다.
- 서론 없이 결론부터 말한다. 칭찬이나 사과로 문장을 시작하지 않는다.
- 코드를 줄 때는 **"어느 파일의 어디에 넣는지"** 를 반드시 함께 말한다.

## 정확성
- 모르면 모른다고 말한다. 그럴듯하게 지어내지 않는다.
- 확인하지 않은 것을 "됐습니다"라고 말하지 않는다. **실행해서 확인한 뒤에 말한다.**
- 라이브러리 이름·버전·명령어는 추측하지 말고 확인한다.

## 안전
- 되돌릴 수 없는 명령(파일 삭제, force push, DB 초기화) 전에는 반드시 확인을 받는다.
- 내가 요청하지 않은 파일은 건드리지 않는다.
```

> 💡 **글로벌과 프로젝트를 어떻게 나누나?**
> - **글로벌** = "나"에 대한 것 (한국어로 답해라, 비전공자다, 결론부터 말해라)
> - **프로젝트** = "이 프로젝트"에 대한 것 (기술 스택, 금지 파일, 실행 명령어)

## 5. 🔧 규칙 파일 3종 비교 — 어디에 무엇을 적나

| | `~/.gemini/GEMINI.md` | 프로젝트 `AGENTS.md` | `.agents/rules/*.md` |
|---|---|---|---|
| **적용 범위** | 내 PC 전체 | 이 프로젝트 | 이 프로젝트 |
| **우선순위** | 1️⃣ 가장 높음 | 2️⃣ | 3️⃣ |
| **다른 AI 도구도 읽나** | ❌ Antigravity 전용 | ✅ **Claude Code·opencode·Cursor 등도 읽음** | ❌ |
| **적을 내용** | 내 개인 취향·응대 방식 | ⭐ **프로젝트 규칙 (기본은 여기)** | 주제별로 쪼갠 세부 규칙 |
| **파일 개수** | 1개 | 1개 | 여러 개 가능 |

> ### 🎯 **처음 시작하는 분께**
> **`AGENTS.md` 하나만 만드십시오.** 나머지는 필요해질 때 늘리면 됩니다.
> `.agents/rules/` 는 규칙이 200줄을 넘어갈 때 쪼개는 용도입니다.

## 6. ✅ 등록 후 반드시 확인할 것

Antigravity Agent 패널에 이렇게 물어보십시오.

```
지금 적용되고 있는 규칙을 3줄로 요약해줘.
그리고 이 프로젝트에서 네가 절대 수정하면 안 되는 파일이 뭐야?
```

| 결과 | 판정 |
|------|------|
| 내가 적은 내용을 그대로 말함 | ✅ 정상 등록됨 |
| "규칙이 없다"고 함 | ❌ 파일 위치 확인 (프로젝트 **최상단**인지) |
| 일반론만 말함 | ❌ Activation을 **Always On** 으로 바꿀 것 |
| 일부만 말함 | ⚠️ 규칙이 너무 김. **줄이십시오.** |
