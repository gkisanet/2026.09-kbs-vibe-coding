# 🧭 심화 — AI 엔지니어링의 지형도

> **대상**: 이 교육의 **강사 본인**. (수강생 배포용이 아닙니다)
> **목적**: 「하네스, 루프, 그래프 이해하기」 영상에서 **맥락이 생략된 채 지나간 개념들**을 전부 복원해서,
> 강사가 이 분야의 지형을 스스로 그릴 수 있게 하는 것.
> **핵심 메시지**: **"용어는 계속 바뀌지만, 바뀌는 이유는 하나다 — 모델이 좋아질 때마다 '일의 절차를 누가 들고 있는가'의 경계선이 움직인다."**

---

## ⚠️ 먼저 알아두실 것

이 폴더의 내용은 **`교육자료 배포/` 폴더보다 두세 단계 위 난이도**입니다.
배포 교재가 "AI가 무엇인가"를 다룬다면, 여기는 **"AI를 일 시키는 시스템을 어떻게 설계하는가"** 의 최신 논쟁을 다룹니다.

그리고 다루는 용어의 절반은 **나온 지 1~3개월밖에 안 된 것들**입니다.
영상에서도 이렇게 말합니다.

> "루프는 두 달 됐고, 그래프는 한 달 됐기 때문에
> 여기서부터는 굉장히 검증이 안 된 단어라고 보이는 게 맞긴 합니다."
> "엑스에서 그래프 엔지니어링이라고 얘기하는 포스트의 한 99%는 다 AI 슬롭같이 보이는 경향이 있어요."

그래서 이 자료의 태도는 이렇습니다.

| 태도 | 내용 |
|------|------|
| ✅ **개념의 계보를 이해한다** | 왜 이 단어가 필요했는지, 무슨 문제를 풀려고 했는지 |
| ✅ **양쪽 의견을 다 본다** | "가치가 있다" vs "그냥 버즈워드다" — 둘 다 근거가 있음 |
| ❌ **용어를 외우지 않는다** | 반년 뒤에 절반은 사라질 단어들입니다 |
| ❌ **최신 용어를 수업에 넣지 않는다** | 배포 교재는 지금 상태로 두는 게 맞습니다 (→ **8번 문서** 참고) |

# 🔑 한 장 요약 — 이 폴더 전체를 5분에

## 1. 딱 하나의 문장

```

│   AI 엔지니어링의 역사 =                                              │

│    사람 쪽에서 모델 쪽으로 계속 밀려온 역사                            │
│                                                                      │
└──────────────────────────────────────────────────────────────────────┘
```

## 2. 그래서 이런 주기가 반복됩니다

```
   ┌──────────────────────────────────────────────────────────┐
   │                                                          │
   │   ① 모델이 좋아진다                                       │
   │        ↓                                                 │
   │   ② 사람이 손으로 짜던 절차가 모델 안으로 "흡수"된다  ← 수축 │
   │        ↓                                                 │
   │   ③ 손이 남으니 사람은 더 어려운 일을 시킨다               │
   │        ↓                                                 │
   │   ④ 더 어려운 일 = 새로운 실패 모드가 생긴다               │
   │        ↓                                                 │
   │   ⑤ 그 실패를 막을 새 장치를 "한 층 위에" 만든다     ← 팽창 │
   │        ↓                                                 │
   │   ⑥ 그 장치에 새 이름이 붙는다  ← 여기서 신조어 발생        │
   │        ↓                                                 │
   │   ①로 돌아감                                              │
   │                                                          │
   └──────────────────────────────────────────────────────────┘
```

영상의 마지막 정리가 정확히 이 이야기입니다.

> "성능이 높아질 때마다 플로우가 흡수되는 것까지는 좋은데,
> 그게 다시 또 일을 많이 하고 싶어 하니까
> 그런 것들을 통제하려고 **더 높은 계층에 새로운 게 등장한다.**
> 이런 식의 좀 **팽창하는 과정**이라고 볼 수 있을 것 같아요."

## 3. 그 결과로 생긴 용어 행렬

| 시기 | 병목(문제) | 대응(해법) | 붙은 이름 |
|:----:|-----------|-----------|----------|
| 2022~23 | 모델이 지시를 잘 못 알아들음 | 입력 문장을 잘 쓴다 | **프롬프트 엔지니어링** |
| 2023~24 | 자율 에이전트가 망가짐 | 사람이 절차를 플로우차트로 고정 | **에이전틱 워크플로우 / 그래프 (1세대)** |
| 2025 | 일이 길어지자 창이 오염됨 | 무엇을 넣고 뺄지 관리 | **컨텍스트 엔지니어링** |
| 2025 | 에이전트가 엉뚱한 짓을 함 | 도구·권한·검증·문서 구조 전체 설계 | **하네스 엔지니어링** |
| 2026 상반기 | 에이전트를 계속 사람이 붙어서 굴려야 함 | 목표만 주고 스스로 돌게 | **루프 엔지니어링** |
| 2026 여름 | 자율 루프가 의도에서 이탈함 | 경로를 다시 결정론으로 고정 | **그래프 엔지니어링 (2세대)** |

## 4. ⭐ 가장 중요한 통찰 — "왜 통제하는가"가 바뀌었다

이게 영상에서 **가장 값진 대목**이고, 대화 도중에 즉석으로 튀어나온 이야기입니다.

```
┌───────────────────────────────────────────────────────────────────┐
│  2024년의 그래프 (LangGraph 시대)                                  │
│  ────────────────────────────────                                 │
│  통제하는 이유: 모델이 멍청해서                                     │
│                (= 능력이 없어서 못 함)                             │
│  통제 방식:     "이 길로만 가"  — 능력 부족을 레일로 보완            │
│                                                                   │
├───────────────────────────────────────────────────────────────────┤
│  2026년의 그래프 (지금)                                            │
│  ────────────────────────────────                                 │
│  통제하는 이유: 모델이 내 의도를 몰라서                             │
│                (= 능력은 있는데 딴 데로 감)                        │
│  통제 방식:     "이 길로 가야 하는 이유가 이거야" — 의도를 구조로 고정 │
└───────────────────────────────────────────────────────────────────┘
```

영상 원문:

> "예전에는 LLM이 멍청해서 통제를 해야 됐잖아요. 실수를 자꾸 하니까.
> 근데 지금은 또 훨씬 똑똑해졌는데, **통제를 해야 되는 이유가 멍청해서가 아닐 것 같다**…"
> "지금은 멍청해서가 아니고, **의도한 대로 가게 하려고** 통제를 하는 거죠."
> "이거는 멍청해서가 아니고, 사실은 그냥 얘가 어떻게 해야 될지를 **지침을 받지 않았기 때문**이거든요."

> 🎯 **강사가 가져갈 한 줄**
> "그래프 엔지니어링은 2024년으로 되돌아간 게 아니다.
> **같은 모양의 해법이지만, 푸는 문제가 다르다.**
> 2024년은 *능력*을 보완했고, 2026년은 *정렬(의도)*을 보완한다."

## 5. 그리고 모든 것의 밑바닥에 있는 것 — 검증

영상에서 짧게 지나가지만 **가장 실무적으로 중요한** 대목입니다.

> "사실 이런 하네스나 컨텍스트나 이런 것들의 거의 모든 관심사는 대부분 개발로 지금 보이죠.
> 이건 왜 그러냐면 **개발이 가장 검증이 쉽기 때문**에 그런 것 같아요."

```
┌─────────────────────────────────────────────────────────────────┐
│  왜 이 모든 논의가 "코딩" 얘기뿐인가                              │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│   에이전트가 스스로 돌려면 → "잘했는지"를 스스로 알아야 한다       │
│                              ↓                                  │
│   그걸 알려면 → 0/1로 딱 떨어지는 채점기가 필요하다               │
│                              ↓                                  │
│   코딩에는 그게 이미 있다 →  테스트 / 컴파일 / CI / 린터           │
│                              ↓                                  │
│   ⭐ 그래서 코딩만 이 잔치를 벌이고 있는 것이다                    │
│                                                                 │
│   ⚠️ 뒤집으면:                                                   │
│   채점기가 없는 업무(기획서 작성, 편성 판단, 원고 윤문)는          │
│   루프도 그래프도 지금은 잘 안 된다.                              │
│   → 이게 방송국 업무에 그대로 적용되는 판단 기준입니다             │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

## 6. 논쟁 지형 — 어느 쪽에 서든 근거가 있습니다

| | **"하네스/루프/그래프는 중요하다"** | **"그냥 버즈워드다 (무용론)"** |
|---|---|---|
| **주장** | 모델을 못 바꾸면 하네스를 고쳐야 한다.<br>지금 성능 차이의 대부분은 하네스에서 온다 | 모델이 똑똑해지면 다 없어진다.<br>실제로 하네스는 **더하는 게 아니라 덜어내는** 방향으로 가고 있다 |
| **근거** | 같은 모델이어도 클로드 코드에 넣느냐 맨 API로 부르느냐에 따라 결과가 완전히 다름 | 3년 전 모델을 지금 하네스에 넣으면 그래도 망가짐 → 결국 **모델이 주역**이라는 증거 |
| **영상의 입장** | "진짜 가치가 있습니다" | "저도 동의하는 부분이 있습니다" |
| **누가 처음 말했나** | — | **하네스라는 단어 자체가 원래 이쪽 진영의 조롱조 표현이었음** (→ 4번 문서) |

> 💡 **양쪽 다 맞습니다.** 정확히는:
> **"하네스는 장기적으로 얇아지지만, 지금 이 순간에는 결과를 좌우한다."**
