# AutoReport 교육자료 — AI와 함께하는 업무 자동화 개발

> **대상**: 프로그래밍 경험이 없거나 적은 방송기술직 직원  
> **목표**: Antigravity IDE + AI를 활용하여 업무 자동화 Chrome 확장을 직접 만들 수 있는 **사고 구조**를 체득  
> **전제**: 코드를 외우는 것이 아니라, **"무엇을 자동화하고 싶은가"를 정확히 표현하는 능력**이 핵심  

---

## 0. Context 관리: AI 활용의 핵심 원리

### 0.1 왜 Context가 중요한가
- **AI는 "기억력이 제한된 초능력 신입사원"**: 대화 세션이 종료되면 모든 이전 내역을 잊어버린다.
- **대화가 길어지면 성능 저하**: Context Window(작업 기억 공간)가 가득 차면 슬라이딩 윈도우로 이전 지침을 잊고 환각(Hallucination)이 발생한다.
- **토큰 = 비용**: 대화가 길어질수록 질문 하나를 던져도 과거 전체 대화 내역(입력 토큰)이 매번 재전송되어 요금이 폭증한다.

### 0.2 AI에게 지식을 주는 3가지 방법 비교
| 방법 | 비유 | 비용 | 적합한 상황 |
|------|------|------|-----------|
| **Context 주입** | 매번 매뉴얼 전체를 들고 가기 | 💸 비쌈 | 단기 작업, 파일 1~2개 수준의 프롬프트 |
| **RAG (검색 기반 생성)** | 색인표에서 필요한 1~2 페이지만 찾아서 보기 | 💵 적당 | 대용량 사내 매뉴얼, FAQ 기반 Q&A 시스템 |
| **학습 (Fine-Tuning)** | 직원에게 신입사원 교육 3개월 시키기 | 💰 초기 비용 큼 | 특정 도메인 전용 사내 모델 구축 |

### 0.3 이 프로젝트의 Context 관리 구조
AutoReport 프로젝트는 AI(Antigravity)와 지속적이고 일관된 개발 협업을 위해 `docs/` 폴더 내에 Context 관리 시스템을 갖추고 있다:
- `docs/CONTEXT.md`: 프로젝트 전체 아키텍처 및 Mermaid 시각화 지도로 AI에게 전달.
- `docs/HANDOVER.md`: 세션이 끊겨도 1초 만에 이전 작업 및 다음 태스크를 복구하는 인수인계 메모리.
- `docs/LESSONS.md`: 발생했던 버그와 오답 노트를 기록하여 AI가 같은 실수를 반복하지 않도록 방지.

## 1. 교육 철학: "코드"가 아니라 "문제"를 먼저 보라

### 1.1 개발자가 아닌 사람이 코딩할 수 있는 시대

과거에는 코드를 한 줄 한 줄 직접 타이핑해야 했다. 지금은 **AI에게 "무엇을 하고 싶다"고 말하면 코드를 만들어주는 시대**다. 단, AI가 좋은 코드를 만들려면 **좋은 질문**이 필요하다.

> 💡 **핵심 비유**: AI는 능력 있는 신입 사원이다. 무엇을 만들어야 하는지 **정확하게 설명**하면 잘 만들지만, "알아서 해"라고 하면 엉뚱한 결과가 나온다.

### 1.2 이 프로젝트의 시작점

```
홍영기 개발자의 일상:
  1. TVDSS에서 편성표를 확인한다 (데이터는 이미 존재)
  2. 같은 내용을 현업일지에 수기로 작성한다 (반복 작업)
  3. 같은 내용을 다시 ERP에 한 건씩 입력한다 (이중 수작업)

  → "왜 컴퓨터가 자동으로 못 해주지?"
```

이 **"왜?"**라는 한 마디가 전체 프로젝트의 출발점이다. 프로그래밍을 모르더라도, **"이 반복 작업이 불필요하다"는 인식**만 있으면 시작할 수 있다.

## 2. Antigravity IDE 환경 세팅

### 2.1 필요한 것

| 항목 | 설명 |
|------|------|
| **Antigravity IDE** | AI 코딩 도우미가 내장된 코드 편집기 |
| **Chrome 브라우저** | 확장 프로그램을 설치하고 테스트할 브라우저 |
| **프로젝트 폴더** | 코드 파일을 모아둘 작업 공간 |

### 2.2 초기 세팅 단계

```
단계 1: Antigravity IDE 설치 → 실행
단계 2: "폴더 열기"로 빈 프로젝트 폴더를 연다
단계 3: AI 채팅 패널을 연다 (보통 화면 오른쪽)
단계 4: 첫 대화를 시작한다 ← 여기서부터가 진짜 시작
```

### 2.3 User Rules 설정 (중요!)

AI에게 **기본 규칙**을 설정해두면, 매번 같은 말을 반복하지 않아도 된다.

AI 채팅에 이렇게 말하면 된다:

```
"이 프로젝트에서는 한국어로 대화하고, 코드 주석도 한국어로 써줘.
Chrome Extension Manifest V3로 개발하고, 프레임워크 없이 Vanilla JavaScript만 사용해.
복잡한 코드에는 한글 주석을 필수로 넣어줘."
```

## 3. AI에게 질문하는 사고 구조

### 3.1 핵심 원칙: "문제 → 재료 → 조립 → 점검"

이 프로젝트의 개발 과정은 정확히 네 단계의 사고를 반복한 것이다:

```
┌───────────────┐
│ ① 문제 정의    │  "뭐가 불편한가?"
└───────┬───────┘
        ▼
┌───────────────┐
│ ② 재료 확인    │  "필요한 데이터는 이미 어디에 있는가?"
└───────┬───────┘
        ▼
┌───────────────┐
│ ③ 조립 방법    │  "어떤 기술로 연결하면 되는가?"
└───────┬───────┘
        ▼
┌───────────────┐
│ ④ 검증/개선    │  "실제로 써보니 뭐가 불편한가?" → ①로 돌아감
└───────────────┘
```

### 3.2 실전: 각 단계에서 AI에게 한 질문들

#### 1단계: 현업일지 자동 생성

| 단계 | AI에게 한 질문 | 사고의 흐름 |
|------|---------------|------------|
| 문제 | "매일 같은 프로그램 목록을 수기로 작성하고 있어" | 불편함 인식 |
| 재료 | "TVDSS라는 시스템에 API가 있는데, 여기서 데이터를 가져올 수 있을까?" | 데이터 소스 확인 |
| 조립 | "Chrome 확장 프로그램으로 TVDSS API를 호출해서 일지를 자동 생성하고 싶어" | 기술 선택 |
| 점검 | "CORS 에러가 나는데 어떻게 해결하지?" | 실행 중 문제 해결 |

#### 3단계: ERP 실적 등록 자동화

| 단계 | AI에게 한 질문 | 사고의 흐름 |
|------|---------------|------------|
| 문제 | "ERP 실적 등록 페이지에 입력할 필드가 20개가 넘어" | 불편함 인식 |
| 재료 | "ERP 페이지의 HTML 구조와 JavaScript 함수를 어떻게 파악할 수 있지?" | 시스템 분석 필요성 인식 |
| 조립 | "Content Script로 ERP 페이지에 도우미 UI를 삽입하고 싶어" | 기술 방향 결정 |
| 점검 | "setTeamData 함수를 호출하면 에러가 나. Content Script에서 페이지 함수를 호출하는 방법이 필요해" | 구체적 문제 해결 |

### 3.3 좋은 질문 vs 나쁜 질문

| ❌ 나쁜 질문 | ✅ 좋은 질문 |
|-------------|------------|
| "코드 짜줘" | "ERP 페이지에서 결재자 사번을 자동으로 채우는 Content Script를 만들어줘" |
| "안 돼" | "이 에러가 나. 원인은 Content Script의 Isolated World 때문으로 추정되는데, 페이지 함수를 호출할 방법이 있어?" |
| "전부 자동으로" | "먼저 결재자 사번만 자동으로 채우는 것부터 시작하자. 나중에 근무자와 WBS도 추가할 거야" |

### 3.4 핵심 사고법: "작게 시작하고, 하나씩 확장하라"

이 프로젝트는 한 번에 만든 것이 아니다. **6단계에 걸쳐 점진적으로** 만들었다:

```
1단계: 현업일지 자동 생성 (TVDSS → 일지 뷰어)
  ↓ 여기서 멈춰도 가치 있는 결과물
2단계: 약칭 관리 (Google Sheets)
  ↓ 더 편해짐
3단계: ERP 도우미 UI (체크박스, 셀렉트박스, 템플릿)
  ↓ 수동 입력 부담 대폭 감소
4단계: 엑셀 → ERP 파이프라인
  ↓ 이중 작업 제거
5단계: 건별 입력 + 저장 제어
  ↓ 안전성 확보
6단계: 플로팅 창 + 버그 수정
  ↓ 사용성 개선
```

> ⚠️ **초보자 실수**: "완성품부터 만들려고 한다" → 실패 확률 99%  
> ✅ **올바른 접근**: "한 가지 기능부터 동작하게 만든다" → 성공 후 확장

## 4. Chrome Extension 개발 — AI와 함께 시작하기

### 4.1 AI에게 프로젝트 초기화 요청하기

**첫 번째 프롬프트 예시:**

```
"Chrome Extension Manifest V3 프로젝트를 만들어줘.
이 확장은 erp.kbs.co.kr 사이트에서 동작하는 Content Script가 필요해.
일단 ERP 페이지가 로드되면 콘솔에 'AutoReport 로드됨'이라고 출력하는 것부터 시작하자."
```

이 한 마디로 AI가 만들어주는 것:
- `manifest.json` — 확장 설정 파일
- `contentscript.js` — ERP 페이지에 주입되는 스크립트

### 4.2 결과 확인하기

```
1. Chrome에서 chrome://extensions 접속
2. "개발자 모드" 활성화
3. "압축해제된 확장 프로그램을 로드합니다" 클릭
4. 프로젝트 폴더 선택
5. ERP 사이트에 접속
6. F12 → 콘솔 탭에서 "AutoReport 로드됨" 확인 ✅
```

> 💡 **여기까지 되면 50% 성공이다.** 확장이 ERP 페이지에서 실행된다는 것을 확인했으므로, 이제 기능을 하나씩 추가하면 된다.

## 5. 기능별 AI 프롬프트 수업

### 수업 1: 결재자 사번 자동 입력

**AI에게 줄 프롬프트:**
```
"ERP 페이지가 로드되면, #TEMP_ZSUPER 입력란에 '30883'을 자동으로 채워줘.
그리고 URL의 쿼리 파라미터에서 ZUSDT 값을 가져와서 #TEMP_ZBDATE에도 채워줘."
```

**확인 방법:** ERP 실적 등록 페이지 접속 → 결재자란에 값이 자동으로 들어가 있는지 확인

---

### 수업 2: 외부 API 호출 (CORS 우회)

**AI에게 줄 프롬프트:**
```
"Content Script에서 tvdss.kbs.co.kr의 API를 호출하면 CORS 에러가 난다.
Chrome 확장의 Background Service Worker를 만들어서 API 호출을 중계하고 싶다.
popup에서 background로 메시지를 보내면, background가 API를 호출하고 결과를 돌려주는 구조로 만들어줘."
```

**확인 방법:** F12 → 콘솔에서 API 응답 데이터가 출력되는지 확인

---

### 수업 3: DOM 조작 — 헬퍼 UI 추가

**AI에게 줄 프롬프트:**
```
"ERP 페이지의 근무자 입력란(#ZENAMET_TXT) 바로 아래에 체크박스 UI를 추가하고 싶다.
체크박스는 3개 조 × 4개 직종으로 구성하고, 체크하면 해당 사번을 ERP 폼에 채워줘.
기존 ERP 페이지의 이벤트를 깨뜨리면 안 되니까 insertAdjacentHTML로 삽입해."
```

---

### 수업 4: 페이지 함수 호출 (브릿지)

**AI에게 줄 프롬프트:**
```
"Content Script에서 ERP 페이지의 setTeamData() 함수를 호출하고 싶은데,
Isolated World 때문에 접근이 안 된다.
인라인 이벤트 핸들러를 이용한 브릿지 함수(execCodeOnPageContext)를 만들어줘."
```

## 6. 디버깅 사고 프로세스

프로그래밍에서 **70%의 시간은 버그 수정**에 쓰인다. AI에게 버그를 설명하는 방법도 중요하다.

### 6.1 버그 보고 공식

```
"[상황] ○○을 했더니
[증상] ○○ 에러가 발생한다/아무 일도 일어나지 않는다
[예상] 원래는 ○○이 되어야 하는데
[추측] ○○ 때문인 것 같다"
```

### 6.2 실제 예시

```
[상황] "플로팅 창에서 입력 버튼을 누르면"
[증상] "ERP 탭을 찾을 수 없다는 에러가 난다"
[예상] "ERP 탭이 열려 있으니 찾을 수 있어야 하는데"
[추측] "currentWindow가 플로팅 창을 가리키기 때문인 것 같다"
```

### 6.3 디버깅 7단계

```
1. 증상 확인 — 정확히 뭐가 안 되는가?
2. 예상 동작 — 원래 어떻게 동작해야 하는가?
3. 실제 동작 추적 — 코드가 실제로 어떤 경로로 실행되는가?
4. 차이점 발견 — 예상과 실제의 차이는 무엇인가?
5. 가설 수립 — 왜 차이가 발생하는가?
6. 검증 — console.log 또는 DevTools 디버거로 가설 확인
7. 수정 — 근본 원인을 해결하는 코드 작성
```

## 7. 핵심 요약 — "코딩을 못 해도 할 수 있는 것"

| 당신이 해야 하는 것 | AI가 해주는 것 |
|-------------------|--------------|
| 반복 작업에서 불편함을 발견한다 | 코드를 작성한다 |
| "뭘 자동화하고 싶은지" 정확히 설명한다 | 기술적 해결 방법을 제안한다 |
| ERP/TVDSS의 URL, 필드명, 버튼 이름을 알려준다 | 해당 시스템에 맞는 코드를 생성한다 |
| F12로 DevTools를 열고 콘솔을 확인한다 | 에러 원인을 분석하고 수정 코드를 제안한다 |
| "이건 되고 저건 안 된다"고 정확히 피드백한다 | 버그를 찾아 고친다 |

> 🎯 **결론: 당신은 "문제를 정의하는 사람"이고, AI는 "해결 코드를 만드는 사람"이다. 둘이 합쳐야 비로소 좋은 도구가 만들어진다.**
